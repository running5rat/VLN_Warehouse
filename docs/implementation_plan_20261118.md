## 1. Model Pipeline

### 1.1 目标结构与模块职责

```text
同步前视 RGB-D + 局部 odom
    ├─ 几何地图更新 ──────────────────────────────┐
    └─ 当前帧 YOLO-E 候选实例 + mask + 异步 OCR    │
                                                ↓
前视历史/当前 RGB + 当前前视检测叠图 + 此前提交的语义地图
+ Previous Route + Previous Local + 相对运动
                                                ↓
                       一次 InternVL TEXT / PREFILL_FOLLOW
                        ├─ Landmark → 源帧实例准入 → 语义地图
                        ├─ Local / Route → 校验 → 下一轮上下文
                        ├─ 两个前视RGB Waypoint → 源帧投影/路线一致性检查
                        └─ <REFLINE> 状态 + 同次 K/V
                                     ↓
                  Reference Decoder + 上下文压缩 → SemanticSnapshot
                                     ↓
前/左/右/后当前观测及有效性 + 局部占用
+ 对齐参考线 + z_sem + 状态/来源年龄
                                     ↓
       九模态 FMAE → 候选硬检查 → Scorer → 跟踪控制 → 新观测
```

| 模块 | 职责与边界 | 当前状态 / 下一动作 |
|---|---|---|
| RGB-D / odom | 提供同帧深度、内外参和源位姿 | Isaac/Habitat 数据链可用；当前为理想仿真 odom，不是 IMU/VIO 能力验收 |
| 几何与语义地图 | 全部有效深度更新几何；选中实例经投影、关联后登记 | 持久化、恢复、异步 OCR 已有实现；身份准确率和实时门槛仍有缺口 |
| YOLO-E / OCR | 定位所有候选实例；识别文字并绑定最明确承载实例 | 仓库固定词表引擎与 R2R 室内词表分开；不得混用类别索引 |
| VLM | Landmark 选择、Local 关系定位、Route 进度和局部路线表达 | 基础 InternVL3-1B；新任务能力未完成正式训练验收 |
| Reference Decoder | 静态名义参考路线、有效长度；不是动态障碍最终动作 | `[32,2]` 路线接口已实现，正式质量未验收 |
| 上下文压缩 | 同次真实 K/V → `z_sem [16,512]` | 接口已存在；不能用零向量或教师特征代替部署语义 |
| FMAE | 多方向最新感知＋参考路线条件，生成平滑、可执行且响应动态障碍的候选 | 部署九模态接口已有；多相机接入、训练/缓存/部署一致性待实施 |
| Scorer / 控制 | 候选核验排序、短前缀执行、独立停车检查 | 规则 Scorer 对照可用；学习型评分尚未训练 |

部署模型接口沿用 v0.7：Reference Decoder 使用8个控制点、32个采样点及前缀mask；上下文压缩为16×512。FMAE首版为512维、3个共享Transformer block、8 heads，横向LEFT/CENTER/RIGHT × 纵向STOP-YIELD/FOLLOW/PROCEED，共九模态；每条30个XY点、0.1秒间隔、Euler 4步，单噪声样本输出形状 `[B,9,1,30,2]`。FOLLOW是沿参考路线跟进/调速，不等于任务层跟随行人。旧单候选训练路径不能因部署已有九模态前向就被认定为完成九模态训练接线。

全局目的地可能不在当前 RGB 内，保留在 Route 和历史语义地图中；当前可执行的局部路线必须遵守所选输出协议的可见性和执行边界。Local 是关系描述，不直接生成或修正定位 TF。跨帧几何对齐依靠 odom；真实机器人阶段需独立验证 odom 漂移和重定位。

### 1.1.1 已确定的前视语义、多方向动作分工

| 分支 | 输入设计 | 不承担的职责 |
|---|---|---|
| VLM／Reference | 前视当前及历史RGB、前视检测叠图、此前提交的语义MapView、Route/Local及相对运动 | 不把每路相机都送入语言模型；前视限制不删除已有地图记忆 |
| AE | 当前前/左/右/后RGB特征、各视图时间/内外参/有效mask、局部几何、机器人状态、对齐参考线和z_sem | 不额外生成第二份Route，不依靠陈旧语义承担全部动态避障 |
| 几何与控制检查 | 可获得的深度／测距、odom、障碍更新时间与footprint | 多路RGB本身不等于已有可靠的米制全向距离 |

首版目标为四方向输入槽位；具体相机安装、视场重叠与帧率在部署配置中冻结，不能仅凭“四路”声称360度无盲区。保留前视RGB-D；侧后方采用深度或测距融合方案提供几何证据，真实硬件选型另行核验。各路独立编码，加方向、相机外参和时间信息，再由动作侧融合；不直接拼成长图，前视特征仅在预处理/编码器一致时共享。

参考线描述名义局部路线，AE处理新障碍并在有效指导范围内避让、减速或停车。高层没有看见侧方通道时，AE不能以“避障”名义自行更换任务路线；触发重新观察或VLM更新。新增视图需要对应训练数据、标定与时延测试，缺失视图用mask关闭，不能复制前视图伪装多方向。

R2R单前视数据继续用于语义/参考线训练；多方向AE在后续仿真采集与合格机器人数据上训练。单前视benchmark与多传感仓库配置分别评测，不混排成绩。

### 1.2 输入冻结：少描述元数据，保留真实证据

近期采用已有 `route_only` 标注约定：首帧 `Previous Route = 原始 instruction`，后续传入最近有效 Route；原始 instruction 永久保存在任务契约和审核侧，但不重复拼入这一实验的模型输入。保留原指令作为每轮输入的方式只做显式对照，不混入同一训练版本。

学生逻辑输入草案如下；实际落地前固定模板、图像顺序、尺寸和哈希，训练与部署使用同一版本：

```text
Previous Route: <all remaining steps, initialized from instruction on first request>
Previous Local: <latest valid landmark-relative description, or unknown>
Motion since previous Local (<age> s): x_m=<x>, y_m=<y>, yaw_rad=<yaw>
Current detectable categories: <same-frame mask-backed categories>
Completion evidence: <confirmed or unverified>

<image>Historical RGB, 3 seconds ago, if available</image>
<image>Historical RGB, 2 seconds ago, if available</image>
<image>Historical RGB, 1 second ago, if available</image>
<image>Current raw RGB</image>
<image>Current RGB with detector boxes and instance IDs</image>
<image>Previously committed semantic map in current source body frame</image>
```

- 当前给模型的是原 RGB 和检测框/ID 叠图；像素 mask 用于投影及审核。不能将叠图称为已输入逐像素分割图。
- MapView 使用历史已提交语义及当时可用几何，不输入最终完整地图，也不增加文字地标目录。
- 相对运动为 `inverse(T_odom_previous_local) @ T_odom_current`；当前车体在上一 Local 源车体系中的位姿，x 前、y 左、米，yaw 逆时针弧度。
- Local 超过 30 秒或 odom epoch 变化时失效。历史关系不能冒充当前可见事实。
- `Completion evidence` 必须来自可获得的完成核验。当前 R2R 没有完整到达证据的样本保持 `unverified`；不由末帧、空路线或目标隐藏坐标自动确认。程序侧完成核验缺失也是工程待办，不能全归因于模型。
- 不发送 Progress、详细执行事件表、Map landmarks 表、batch/image ID、哈希、版本及完整候选参数表。它们保存在审计侧。
- 教师可使用详细规则；学生 SYSTEM 要短，但字段含义和可用观测一致。短模板目前仍须接线、训练及自由生成验证，不能直接删掉现有规则就宣称已优化。

### 1.3 输出和递归提交

当前教师原始输出为三字段 JSON：

```json
{
  "landmark": ["sign"],
  "local": "By sign 01/4R, facing toward sign 02/4R.",
  "route": "Continue to the aisle end, turn left, then approach the extinguisher and stop."
}
```

这是格式示例，不是待写入数据集的答案。教师不输出 waypoint/ref_line，不读取未来轨迹。下一版本学生 TEXT 保留五标签，仅将Waypoint改为两个：

```text
<landmark>[categories]</landmark>
<local>landmark-relative position and heading, or unknown</local>
<Route>remaining navigation commands, or DONE</Route>
<waypoint>(u1,v1);(u2,v2)</waypoint>
<REFLINE>
```

| 字段 | 下一版本约定（代码迁移后启用） |
|---|---|
| Landmark | 最多 3 个当前检测类别；不生成 image_id，不将 OCR 编号拼入 category；类别准入不等于精确选择某一个实例 |
| Local | 英文，最多 **90 字符**；描述位置与朝向，有证据才引用编号；不能只抄场景描述冒充定位 |
| Route | 英文，最多 600 字符；只写剩余导航命令，保留未完成步骤、顺序、目标和最终停等；只凭观测与相对运动删除已完成部分 |
| DONE | 仅在完成证据 confirmed 且整个任务完成时使用；模型文本不直接解除执行器的核验职责 |
| Waypoint | 两个有序的前视RGB原图像素点 `[u,v]`，或 `[]`；近锚点在前、远锚点在后；禁止混合像素与米 |
| REFLINE | 查询 token；连续参考线由实际处理该 token 的 hidden state 解码，不是语言模型生成数组 |

当前 v0.7 源稿中的 Local 80 字符、每轮 Instruction，以及旧 Route JSON 示例是历史约定；最近标注使用 90 字符、route-only、自然语言 Route。落地时以具体运行配置与版本为准，先统一学生/教师文档映射，再冻结新版本。教师标点限制与 `Inferred:`、`01/4R` 存在冲突，必须在下一模板版本修正；旧响应保留，不静默重写。

递归更新顺序：冻结输入 → 一次请求 → 保存原文 → 校验 → 原子提交 Route/Local/快照状态 → 对同源 mask/OCR 入图 → 下轮读取。坏帧隔离，继续使用最近有效状态并记录年龄；Map/Route/Local 不跨任务串用。合法 Route 可更新而该轮参考线不可执行，不能拼接上一轮旧参考线伪装一致快照。

`PREFILL_FOLLOW` 保留独立接口：处理查询，不生成文本、不更新 Route、不发布静态地标。当前静态 TEXT 数据不能复制为跟随监督。

### 1.4 两个Waypoint与连续ReferenceLine

| 协议／路径 | 输入/输出坐标与执行 | 用途与状态 |
|---|---|---|
| 历史v0.7训练路径 | 源车体系米制五锚点；真实 `<REFLINE>` Decoder → FMAE → 控制 | 既有数据与checkpoint，保持原版本读取 |
| 历史 `rgb-pixel-waypoint-v1` | 五个原RGB像素点 → 深度投影 → 工程PCHIP → 控制 | 旧demo，不冒充Decoder/FMAE |
| 下一版本 `rgb-pixel-waypoint-v2-two-anchor` | 两个原RGB像素锚点；真实 `<REFLINE>` Decoder输出车体系连续线 → FMAE → 控制 | 本版确定的目标接口，解析/训练/部署迁移待实施 |

像素协议要求可见地面的局部前缀，不将标牌上的点当成车辆目标。原图尺寸、缩放/裁剪、内参和外参必须可追溯；深度无效时拒绝，拟合段还须检查遮挡和通行。车头至最近可见点的近端盲区单独检查。仅“像素在图内”不证明路线可通行。

Waypoint是可解释的稀疏视觉锚点，ReferenceLine是密集路线；本轮不删除任一输出。REFLINE查询位于Waypoint之后，Decoder读取实际处理后的hidden state；不能用两个点的插值冒充Decoder结果。两个点不足以唯一确定弯曲路线，连续形状由参考线监督学习，并对自由生成时的锚点/路线一致性独立验收。

标签生成：从批准的密集参考线中取前视可见、同帧深度支持的连续局部前缀，按弧长选其中点与远端作为两个锚点，再投影到原RGB。保留原始密集轨迹、完整参考线候选与裁剪依据；模型局部参考线监督使用同一有效前缀。相机近端盲区保留单独几何检查，不能标为RGB可见。短线不足以产生两个可区分锚点时输出`[]`并记录无有效局部指导；不复制点凑数，也不据此认定任务完成。

迁移顺序：版本化schema与两点解析/约束 → 从原密集GT重新派生两点（不能截取旧五点前两点）→ 人工审核投影 → 训练/推理共用模板 → Decoder自由生成一致性 → 控制验收。原参考线仍为32点，动作仍为30步；减少的是文本锚点数，不是连续路线/动作的采样点数。旧五点协议通过显式适配保留，不静默改变其数值含义。

像素工程对照若仍使用拟合器，须针对两点重新检查起始朝向、曲率及碰撞；不能假定旧五点PCHIP配置直接适用。新生成的两点结果需重新实际闭环，不能沿用旧视频作为通过证据。

最新两任务 Codex 视频为既有轨迹回放：37 帧，24 帧非空投影通过、13 帧空点；24 帧控制诊断均被占据/未知检查拒绝。旧米制 demo 的实际运动不能证明新像素预测完成闭环。

### 1.5 原地旋转：最小接口补充，尚待实施

位置 waypoint 不包含 yaw；`[]` 目前不能区分停止、无路线和需要旋转。不能用画面外像素、横向虚假路径或隐藏世界路线补出转弯。

建议在像素 demo 新协议中增加 `motion`，或等价的独立朝向字段：

```json
{"waypoint": [], "motion": {"type": "rotate", "yaw_delta_deg": 90}}
```

`rotate` 以请求源朝向为基准，正值左转；执行器锁定一次目标朝向，根据 odom 扣除已转角，不每周期追加 90°。可选 `face_pixel` 表达朝向当前图像内某目标，利用相机视线方向求 yaw，而非把像素投影成驶入位置。`stop` 与无效输出要有独立状态。

落地顺序：版本化 schema/解析 → yaw-only 示范标签 → 角度与源时间测试 → 静止 Isaac 左/右转 → 旋转期间新 RGB 回流 → 新有效输出接管。旋转保持平移速度为零，检查车体旋转扫掠范围；前视不等于全向安全。缺少侧后方证据时停等或补看，不以“原地转动”承诺可完成全部避障任务。

这是近期讨论的**建议**，当前未接入训练/控制。正式 FMAE 的 XY-only 输出同样不能充分表示纯旋转；后续应评估 SE(2) 或独立 yaw 通道，不把原地转向数据误标为 STOP。

## 2. Training Schedule

### 2.1 当前训练基础与限制

人工 `manual-static-004` 的 10 个批准关键帧已完成一次 100 步训练链路诊断：文本/参考线 loss 下降、冻结检查、严格重载通过。它是同 episode 拟合，不是泛化成绩，诊断 checkpoint 不作为正式实验初始化。

当前默认是语言全部层 Q/K/V/O 的 **r=16** LoRA；最近讨论的全部层 Q/V **r=8** 尚未切换。若作为低成本实验采用 r=8，需配置化 target_modules，记录实际匹配层数与参数数目，检查保存/部署严格重载。基础模型及视觉编码器冻结，Reference Decoder 单独训练。约 54 万 Q/V LoRA 参数只是依据本地结构计算的规模，不包括 Decoder，也不决定“最佳数据量”。

TIC-VLA 原论文采用冻结视觉编码器的语言侧全参数 SFT，不是 r=8 LoRA；其硬件、数据量不能直接作为本项目最低要求。既有 10 帧诊断日志的 PyTorch 峰值分配约 4.64 GiB、稳态优化器步约 1.11 s，仅属于旧 r=16 输入与小样本环境。正式 R2R 应先测 100–300 步，再估算时间；不将其机械外推作为工期承诺。

### 2.2 阶段、数据与冻结边界

确定路线：**InternVL3-1B＋LoRA＋完整训练Reference Decoder → LoRA秩对照 → 模型容量对照 → 数据质量和规模稳定后语言侧全量SFT**。LoRA也是SFT的一种参数更新方式；“全量SFT”在本计划中首先指语言侧全参数更新，视觉编码器继续冻结，不默认连视觉主干一起训练。

| 阶段 | 训练内容 | 数据安排 | 开始条件 / 交付 |
|---|---|---|---|
| A0 接口重验 | 前视短模板＋两个像素锚点；InternVL3-1B、r=16 Q/K/V/O LoRA＋完整Decoder | 从人工批准密集GT和少量批准R2R重新导出；投影不合格字段关闭监督 | 先完成M1；保存loss、梯度、重载、自由生成和显存/吞吐报告；旧100步诊断不能替代 |
| Stage1a-R0 基线 | 基础 InternVL 与 TIC-VLA 初始化的同接口评测，不更新参数 | 固定官方验证子集＋内部开发集 | 固定控制器和传感设定；记录格式失败与停车，不人工补模型输出 |
| Stage1a-R1 规模试验 | VLM LoRA＋Reference Decoder | 先审核后的约 300 任务量级，再 1,000，再 2,000–3,000 | 各组从原初始化重新训练；覆盖建筑/路线/事件；不是保证最佳规模 |
| Stage1a-R2 正式消融 | 几何监督 vs 几何＋Landmark/Local/递归 Route | 相同合格样本和 split；后续单独英语 RxR 扩展 | 固定输出协议、输入与预算；区分预测文本和 teacher-forced 诊断 |
| Stage1a-R3 秩对照 | r=8/16/32，固定全部语言层Q/K/V/O；Decoder全参数训练 | 同一批准manifest与初始化 | 秩单变量对照；Q/V-only另列目标层实验，不与秩同时混改 |
| Stage1a-R4 容量对照 | 同系列InternVL3-1B与2B；4B级候选作为独立跨骨干扩展 | 同一任务、样本和评测；缓存/头维度随骨干重新适配 | 先测1B/2B；跨架构结果不能全部归因为参数量；不沿用不兼容Decoder权重 |
| Stage1a-R5 全量SFT | 最佳候选语言侧全参数＋完整Decoder，视觉仍冻结 | 审核和递归修订稳定、规模试验收益明确的数据 | 先资源预检，再与LoRA匹配训练预算比较；未满足门槛不直接全量训练 |
| Stage1b 仓库静态迁移 | 名称/编号定位、跨任务地图、视野外目标 | 独立仓库任务＋R2R/RxR 保持池；真实仓库先少量试采 | 不用既有 demo 做独立测试；先验证 odom、标定与目标核验 |
| Stage2 动态 FMAE（暂缓） | Flow＋动作投影＋上下文压缩器 | 静态任务对应动态轨迹；合格开源动作数据 | 冻结 VLM/Decoder；缓存真实压缩前 K/V；完成动态小单元后再训练 |
| Stage3 Scorer（暂缓） | 候选分项评分、排序和已知模态可行性 | 当前冻结 Flow 的实际候选＋规则 Oracle 分数 | 先有可执行候选；保留规则对照，生成器更新后重采样校准 |
| Stage4 DAgger / 可选 RL（暂缓） | 失败状态聚合、动作侧改进 | 训练环境真实闭环访问状态、接管与复核 | IL 基线稳定；验证/测试轨迹不回流；RL 单独确定策略概率及预算 |

近期只优先A0、R0/R1；R3从小规模开发试验开始，不将所有规模、秩、骨干和配比做全排列。每个正式对照从匹配的原始初始化独立训练；若追加“从LoRA合并权重继续全量训练”，单独命名为续训试验。动态Lattice＋AL-iLQR、人类动作机器人化和在线RL不作为静态训练启动前置工程。

#### 2.2.1 更新参数、比较方法和升级门槛

- 语义阶段：仅语言LoRA和**整个Reference Decoder**更新；基础视觉/语言权重冻结，动作头、Scorer和未使用的上下文压缩器不更新。记录匹配模块、参数量和梯度，不能将“完整训练Decoder”误称“完整训练VLM”。
- 秩对照：固定target_modules、alpha/r缩放、数据顺序、有效batch、训练样本曝光量和评测；允许同等小预算选学习率并单独记录。保留r=16现有基线。r=8 Q/V作为另一个低成本对照，不能据它与r=16 Q/K/V/O的差异推断纯秩效应。
- 容量对照：优先同系列1B/2B；4B级模型若更换骨干/预训练数据，明确为模型选择而非纯容量消融。比较真实生成、递归Route保持、参考线、闭环指标及端到端p95，不只比较loss或参数量。
- 全量升级门槛：批准数据和修订链可重建；独立布局/建筑划分无泄漏；LoRA在合理调参后仍显示欠拟合或规模收益趋缓；能够承担显存和训练时间。若训练拟合好但验证差，先处理过拟合、场景覆盖和标签问题。
- 单卡4090先做100–300步资源预检；显存包含图像token、激活、优化器、Decoder及并发模型。不得以“LoRA参数少”保证4B多图输入一定能装入24GB；先冻结输入预算再测量。
- Stage2冻结选定VLM与Decoder，训练FMAE、动作侧多视图融合、投影和上下文压缩器；导出该语义checkpoint真实压缩前K/V并注入时延/位姿差。旧单前视动作数据保留缺视图mask，不伪造四路观测。

### 2.3 数据配方与实验控制

Stage1a 第一轮采用 **100% 合格 R2R 导航监督**，先回答 R2R 上是否有效。人工基准默认用于回归，只有明确标记的有限拟合诊断允许更新参数；4 个比较任务也不自动入训练。

首轮试验配比以**采样后的有效训练样本数**为分母，不按库存帧数、视频小时或磁盘大小计算。先选数据池，再在池内按任务/episode/关键事件采样，长视频不因重复帧自动获得更高权重。以下是已纳入计划的起始试验配方，不是已经验证最优的结论：

| 阶段 | 起始采样配方 | 对照与条件 |
|---|---|---|
| Stage1a初始 | 100%批准R2R | 先确认导航与中间监督有效 |
| Stage1a扩展 | R2R 72%＋英语RxR 18%＋空间/指代VQA 10% | 导航子池内部80:20；做辅助VQA 0/10/20%对照，导航部分同比缩放 |
| Stage1b仓库 | 仓库50%＋R2R/RxR保持池40%＋针对性VQA 10% | 对照仓库适应与benchmark遗忘；仓库池内部先约20%恢复/纠正样本，即总量约10%，不是额外加20% |
| Stage2动作（暂缓） | 动态仿真机器人60%＋合格真实机器人30%＋可适配人类轨迹最多10% | 人类数据不合格则关闭该池，并将其额度按2:1分回前两池；不为凑比例伪造尺度/深度/视图 |
| Stage3评分（暂缓） | 按候选风险、失败类型和已核验模态分层 | 无统一文本/动作混比；unknown不作为不可行负例，保留部署分布评估集 |

VQA优先补地标指代、地图与RGB关系、相对方向、历史/当前区分、任务剩余步骤和到达证据；不要求每个VQA都带轨迹，无几何标签关闭相应loss。冻结VLM后的Stage2中，普通VQA不再能通过文本loss改善被冻结的语义模块，不机械沿用Stage1配比。

参考经验：[LightNav-0](https://www.lightorigins.com/en/blog/lightnav-0)第一阶段Pointing/单图VQA/通用视觉及抽象推理/视频推理采样约35.14/25.05/20/19.81%，第二阶段导航动作/VQA为77.6/22.4%；[ABot-N0](https://arxiv.org/html/2602.11598v1#S4)动作与语义联合训练阶段保留约20%推理回放。本项目动作阶段冻结VLM，训练边界不同，不能直接照搬比例。辅助样本成本与梯度占比另行记录，样本比例不等于token或loss比例。

旧文档的仓库70%/外部20%/辅助10%是历史候选，本版首轮仓库配方使用上表50/40/10。真实仓库先以完整任务、路线和关键事件覆盖确定采集量，试采后换算小时，不凭仿真帧数承诺最低录制时长。

每个实验遵守：先采来源/任务，再采 episode/事件；同路线不同指令按组划分；不要通过增加直行重复帧掩盖转弯、停止、重定位和地图依赖样本不足。静态名义路线与动态避让动作不互换标签。

### 2.4 损失、数据量与评测

静态阶段：有效答案token的masked CE（包含两点像素文本），加车体系参考线点、有效长度和有效性监督；两点投影一致性作为独立诊断，几何辅助loss仅在有效投影时启用并记录权重。缺失动作loss为零。未标注路线、明确空路线、有效短路线分别编码。参考线不因文本点数变为2点。

以本地 R2R 120,930 关键帧 / 10,819 任务估算：300 任务约 3,400 个时刻，1,000 约 1.1 万，2,000–3,000 约 2.2–3.4 万。它们是多图上下文训练样本，不是独立场景数；正式导出按实际审核数量统计。没有依据将 r=8 对应成一个固定最佳数据量。

| 验收层 | 检查方式 | 进入下一步的条件 |
|---|---|---|
| 数据/接口 | 来源、坐标、监督 mask、严格重载、冻结梯度 | 确定性检查全部通过；批准样本可完整加载；未标注分支不贡献 loss |
| 拟合 | 同样本 loss、真实自由生成、Decoder 原始数组 | loss 有限且下降；存在真实合法完整输出；不能用强制模板结果代替内容学习 |
| 语义 | 完整 episode 的 Landmark、Local、剩余步骤、错误 STOP/DONE | 对比未训练模型并报告分母与修订量；路线遗漏等关键错误不能因格式通过而忽略 |
| 路线 | 可见/可投影性、米制误差、有效长度、方向、锚点一致性 | 分开报告 teacher-forced 与自由生成；正确方向和有效运动正例不能全为零 |
| 导航 | 固定执行器闭环 SR、SPL、NE、轨迹遵循及停止 | 按对应 benchmark 官方判据；失败/停车全部计入；报告不确定性，不能只展示成功视频 |
| 扩量收益 | 300/1,000/3,000 嵌套数据规模实验 | 验证集改善时扩量；拟合/标签/接口出错时先定位原因，非自动增加 API 用量 |

内部开发数据按建筑/路线组留出；官方 val_unseen 用于约定频次的模型选择，test 不用于调参或生成训练标签。最终主要对照建议至少 3 个 seed，报告均值与波动；先用单 seed 做低成本排错，不将其包装成稳定收益。官方协议与本系统 RGB-D＋理想 odom 的扩展设定分别列出，不混排分数。

### 3.2 固定数据格式与因果边界

沿用 schema v2，不重设计基础容器：

| 命名空间 | 内容 | 约束 |
|---|---|---|
| observation | 图像、历史地图、标定/位姿、任务契约、旧Route/Local、可测事实 | 通过白名单形成prompt；不把整个JSON发送给模型 |
| supervision | 批准文本、参考线/锚点、未来扩展的动作/评分及有效mask | 不能进入教师或学生的观测；缺失不补零标签 |
| provenance | 来源、任务/路线组、布局、协议、模型/标注人、哈希、批准/修订记录 | 不作为模型身份特征；用于去重、审计和复现 |

保留原始yaw、速度、控制和时间轴；纯原地转向没有XY进展不等于停止。R2R回放时间是仿真时间，odom是理想局部位姿，不伪装成真实IMU。

参考线为`[32,2]`、有效前缀mask、0.25m默认弧长间距；旧版五锚点保持原协议。新版本从同一批准路线的可见前缀重新派生两个像素锚点，另存`[u,v]`、原图尺寸、可见性、投影来源和对应几何，不能覆盖旧字段含义。动态绕行不作为静态名义路线GT。

多方向数据在observation中按视图保存RGB、可用深度、时间戳、内外参及有效性；前视VLM输入白名单不自动纳入侧后相机。未来轨迹和隐藏几何继续留在supervision／核验侧，不能通过多视图或地图缓存泄漏。

### 3.3 人工、教师与几何标签流水线

```text
固定来源/split/路线组
→ 同步数据、轨迹、标定核验
→ 因果几何 + 缓存真实mask/OCR
→ 关键帧与参考线覆盖检查
→ 一次教师生成Landmark/Local/Route
→ 当前答案校验并提交地图/递归上下文
→ 保存原文、失败及费用
→ 完整episode人工审核
→ 单独修订版本与依赖重建
→ 批准manifest + 监督mask
→ 训练加载/部署重载验证
```

教师冻结为现有 `qwen3.7-plus` 北京配置：开启思考、2048 thinking budget、8192输出上限、180秒超时、直连；任务内串行，独立任务最多3并发。SYSTEM以当前扩展批次归档的 `qwen-plus-v6-route-only-preserve-v1` 及哈希为准，不因为旧文档仍写v1/v5就回退配置。这里只冻结本地已使用配置，不声明供应商当前价格或型号永不变化。

每帧一次语义请求，不自动补问。超长/格式/类别失败保存原文，后续使用最近有效上下文；API、预算、来源、存储错误停止。恢复先查进程锁、已保存响应、预算指纹、地图提交状态；未知请求只能按明确恢复记录重试，保留原预留与attempt ID，不能降低已发生费用。

### 3.4 审核内容与递归修订

整episode展示所有预定关键帧，遵循 [Agent.md](../Agent.md)：实际RGB/检测图、输入地图、Previous Route/Local/运动、真实prompt及原文、输出字段、示范几何GT、投影/地图状态、来源与时间。

人工重点分六类判断：

1. 当前Landmark是否有同帧实例，是否值得登记；不是仅看类别名匹配。
2. Local位置和朝向是否有RGB/地图支持；OCR冲突、历史推断是否标明。
3. Route是否保留全部未完成步骤、最终目标和停等；是否误把场景描述写进路径。
4. STOP/DONE是否提前、是否停止后又无依据增加动作；记录Completion证据缺口。
5. 地图、OCR归属与实例关联是否错误传播；tentative不等于可靠静态锚点。
6. 几何GT是否同源、可追溯，是否有参考线覆盖缺口；未知空间诊断和实际控制检查分开。

121个规则失败帧全部复核；其余合法帧按整段任务审核，优先转向、目标出现、停止、地图依赖以及历史失败后恢复帧。没有逐字段审核的合法帧仍为候选，不自动设为approved。

人工修订单独存储，原始模型递归链保持原样。若将修订用于训练，重建该版本后续Previous Route/Local；若Landmark选择改变，应重放对应语义地图并复核后续输入。仅替换答案而继续用旧错误地图/历史作为“已修正链”不可接受。不能把这份人工修订链冒充模型原始闭环成绩。

### 3.6 风险与处理顺序

| 风险 | 影响 | 首选处理 |
|---|---|---|
| Route删掉未完成目标 | 递归中永久丢失任务 | 审核与任务保持监督；保留route-only/原始instruction对照，不靠格式约束证明正确 |
| Local漂移或OCR错绑 | 历史地图错误自强化 | 源实例绑定、冲突和不确定性；复核重建修订链 |
| 完成证据缺失 | 末帧不能标DONE | 补可在线复核的目标/停止证据；不借隐藏GT伪造学生能力 |
| 90字符/标点矛盾 | 有用回答被拒绝或含糊 | 明确合法语法，保留原文；新模板单独小规模对照，不静默截断 |
| 路线/布局泄漏 | 验证成绩虚高 | 原始路线组先划分、同源跨发布渠道去重、隔离人工回归集 |
| 像素/米制/yaw混用 | 标签与控制语义错误 | 显式协议和适配，单位与方向测试；纯旋转另通道 |
| 大量几何数据但语义未批准 | 错把库存当训练规模 | 分别统计准备/返回/规则/批准/导出数量 |

### 3.7 一个重建场景生成多个任务：轨迹Oracle的最小职责

**新生成任务没有现成示范轨迹时，需要轨迹Oracle或人工示范。** 仅重写同一已核验路线的指令、从原示范中切取合法子任务时，可以复用已有轨迹，不必重新规划。重建场景提供可观察环境，不能自动提供任务对应的正确动作。

| 数据情况 | 路线来源 | 是否需要新轨迹Oracle |
|---|---|---|
| 同轨迹指令改写／合法子段 | 已核验专家轨迹，重新核对起终点与指令范围 | 不一定；保留来源并按同路线组去重 |
| 新起点、目标、路线顺序或绕行条件 | 静态几何规划＋控制回放，或人工驾驶 | 需要；不能把别的任务轨迹直接配给新指令 |
| 添加行人/车辆后的动态任务 | 动态规划Oracle或人工示范＋独立核验 | 后续动作阶段需要；本轮不提前启用AL-iLQR |

最小静态引擎：

```text
场景采集/重建或既有USD资产
→ 米制尺度、碰撞网格、可通行区域、标定及目标身份核验
→ 先按布局族划分train/dev/test
→ 采样起点/朝向、目标可停邻域、必要的有序途经条件
→ NavMesh或占用图搜索（如A*）生成任务一致的路线
→ 差速控制器在仿真中执行、记录实际轨迹与碰撞/到达结果
→ 任务核验通过后提取静态参考线与两个可见像素锚点
→ 因果RGB-D/地图/历史 → 语义教师 → 递归审核 → 批准导出
```

多步指令必须逐个满足途经条件，不能只规划起点到终点最短路后声称完成“第二路口右转”等要求。对于新合成任务，可先生成可执行路线与途经事件，再生成匹配指令；对于既定用户指令，则先明确可核验的任务约束，歧义任务进入隔离池。运行时仍只输入instruction/剩余Route，生成侧任务条件和全局真值不进入学生观测。

静态Oracle无需先实现AL-iLQR；几何路线必须经robot footprint、转向可执行性、目标停留邻域和实际控制回放核验，平滑后再次检查。存在漂亮渲染但没有可靠尺度、碰撞或深度的3DGS场景，不直接作为米制动作GT。失败路线/碰撞执行归档，不标为成功专家。

语义Oracle与轨迹Oracle分工：教师只根据当时可用输入生成Landmark/Local/Route；几何GT由示范/规划执行产生。核验器可使用隐藏几何和未来轨迹检查一致性，但不能把这些信息灌入教师的Local或学生输入。参考线保持静态名义路线；动态避让另外标动作，不覆盖静态路线。

增加偏离路线、错过路口、朝向误差、相似编号、局部地图/OCR冲突等纠正样本，从扰动后的真实观测重新求解剩余任务，不沿用原状态答案；任务内历史不可能获知的完成步骤不能凭空补入。一个场景生成很多任务不能代替布局多样性，所有同布局变体/配对动态任务/重叠轨迹按组隔离。

可借鉴[ABot-N0 Data Engine](https://arxiv.org/html/2602.11598v1#S3)的导航图、规划与示范混合、偏离恢复样本和推理/轨迹一致性核验；不复制其规模作为本项目采集指标。近期先在现有仓库验证少量新起终点和多步任务，生成—执行—核验通过后再批量化。

## 4. Deployment Optimization

### 4.1 部署路线与运行边界

第一落点是单张 RTX 4090 工作站＋宿主 `/data/isaacsim` Isaac Sim 5.0；离线训练/教师和感知分别使用隔离环境。宿主启动桥接沿用现有脚本，不升级 Isaac 内置依赖来兼容推理库。目标部署平台统一为 NVIDIA Jetson AGX Orin 64GB；车端承载感知建图、VLM、Reference Decoder、FMAE／Scorer 与控制。RTX 4090 保留为训练、仿真与开发平台，PC 耗时不能当端侧验收。

近期推理分工：几何不等待模型；YOLO-E常驻、固定词表特征初始化一次；OCR独立低频队列；一个VLM服务串行处理TEXT/PREFILL，任务内不并发更新递归状态。模型结果通过来源/版本检查发布，地图保持单一写入者。

新设计将多方向图像留在快AE分支：VLM/Reference保持前视图像预算和地图输入；AE对多视图进行有界融合，检测/测距与控制不等待文字生成。传感器掉线或时延过大时保留无效标记，执行范围依据可用观测收缩，不静默退成“完整全向感知”。新增相机、编码和仿真渲染的GPU竞争单独测量。

导航模式只执行一次完整TEXT，不额外再跑一次自由物体问答或实例筛选VLM。独立建图模式可仅生成Landmark；模式变化必须记录实际prompt及分支，不把两次推理统计成一次。

### 4.2 性能目标与测量口径

| 链路 | 沿用目标 | 验收口径 |
|---|---|---|
| 物理步进 | 60 Hz | 仿真步长；不与RGB采集频率混淆 |
| RGB-D / 几何 / 候选分割 | 5 Hz，运动期间实际至少4.75 Hz | 真正处理的不同源帧；几何完整消费；替换/超时计入 |
| 多方向AE观测与融合 | 首版与Flow 5 Hz目标对齐 | 逐路源时间、同步误差、缺帧和新鲜度；不能把4路合计20帧/s称作20Hz完整观测；动态场景再按风险验证是否需提频 |
| 候选mask与投影发布 | p95 ≤500 ms | 源帧提交至界面可读取，不是浏览器刷新间隔 |
| OCR采样与绑定 | 1 Hz；完成率≥95%；p95≤2 s | 包含排队；未选中未绑定、替换、超时单列，不缩小分母 |
| VLM TEXT | 事件触发＋异步更新 | 先测实际服务时间/来源年龄；不能把每2秒采样写成0.5 Hz完成 |
| PREFILL / Flow / 控制 | 1 / 5 / 30 Hz设计目标 | 真前向、合法候选和实际命令分别计数；未训练头不算能力通过 |

这些是待验收目标，不是当前均已达标。原建图实验有语义延迟/身份质量未通过项。类别/实例准入后正式入图频率另报，不将5 Hz候选发布等同5 Hz正式语义登记。

每次请求记录 `source / submit / start / ready / commit / browser-render` 时间，以及图像编码、prefill、decode、Decoder、压缩器、Flow、候选检查、控制耗时，报告p50/p95、token数、GPU峰值、队列长度和丢帧。嵌套阶段不能重复相加；跨主机时间须校准。启动/预热与运动期间统计分离。

### 4.3 优化顺序：先量测，再压缩

| 优先级 | 动作 | 正确性保护 / 输出 |
|---|---|---|
| O0 | 固定版本、模型常驻、预热、分阶段计时、只读回放基准 | 同一批输入比较；记录图像token和生成token，避免把prompt长度当全部延迟 |
| O1 | 教师/学生SYSTEM分开；共用短学生模板；五点改两点；取消二次问答 | 真实decode token/时延对照；不能按5→2推算总耗时降低60%；不删未完成Route换速度 |
| O2 | 前缀/视觉特征缓存、词表特征缓存、SDPA/FlashAttention、异步写盘 | 只复用确实不变的输入；动态地图、位置和历史顺序变化需失效；不盲复用跨请求KV |
| O3 | 固定类别YOLOE-v8s TensorRT FP16；OCR CPU线程；候选与文字解耦 | 引擎类别/hash与词表一致；无静默回退；量测GPU争用与绑定错误 |
| O4 | 按收益评估模型量化、推理引擎、解码优化 | 坐标、数字编号、Route保持、Decoder/KV接口回归；不只比较tokens/s |
| O5 | 后续MapEncoder、历史token压缩及端侧移植 | 新训练/缓存版本、端到端收益；与MapView基线分开，不阻塞当前Stage1a |

LoRA r=8主要降低训练可更新参数，不自动大幅减少部署decode耗时。部署可评估合并adapter，但必须保存原adapter/基础权重hash并做合并前后输出对照。不同backend对实际 `<REFLINE>` hidden state和K/V可访问性需验证，不接受只支持文本输出却声称完整快照可用。

### 4.3.1 DriveVLM的可借鉴优化及本项目落点

依据[DriveVLM正式论文](https://proceedings.mlr.press/v270/tian25c.html)及其[附录D部署说明](https://raw.githubusercontent.com/mlresearch/v270/main/assets/tian25c/tian25c.pdf)。以下均为待实施/待测方案，不是本项目已取得的加速结果。

| 论文中的方法 | 本项目建议 | 依赖与验收 |
|---|---|---|
| 慢VLM与快规划系统异步执行 | VLM更新语义与名义路线；FMAE读取最新感知，控制器连续执行短前缀 | 优先落实；分别测语义来源年龄、动作发布与实际控制周期，不能用快系统频率代表VLM频率 |
| LDPNetv2压缩视觉token，裁去非信息区域 | 先缓存不变图像特征，再评估学习型历史/地图token压缩；保留标牌、路口和可通行边界 | 新压缩器需要训练；裁剪必须更新坐标映射，不能直接套用汽车图像裁剪规则 |
| 历史视觉feature memory bank与SE加权融合 | 缓存逐图像视觉特征，以源时间、相对位姿和有效性处理历史 | 编码器、预处理和图像hash变化则失效；视觉特征缓存不等于可任意复用LLM历史KV |
| EAGLE推测解码 | 先剖析TEXT的decode占比，再评估草稿模型和验证成本 | 需要适配/训练草稿模型；核验最终接受token对应的真实REFLINE状态和K/V；PREFILL模式没有长文本decode可加速 |
| 自定义Orin推理框架 | 后续单独做端侧后端与精度回归 | 先验证hidden state/KV导出，再评估INT8/INT4等通用优化；不把这些通用选项全部归因于DriveVLM |

论文报告LDPNetv2减少75%图像token、EAGLE约2.7倍decode加速，以及慢系统约400ms、快系统约130ms。它们属于论文的模型、硬件与输入配置；不能据此预计本项目同比加速，也不能将异步快系统130ms理解为语义指导仅陈旧130ms。

实施顺序固定为：**分阶段计时和异步发布 → 编码特征缓存 → 后端/精度回归 → 学习型token压缩 → 有收益时再做推测解码**。无需训练的工程项先做；压缩器或草稿模型归入后续训练计划。每项以完整请求的p95延迟、地图/编号理解、Route保持、参考线与动作输出为验收依据，不能只看tokens/s。

### 4.3.2 本版部署实施包与消融

| 顺序 | 实施内容 | 验收与回退 |
|---|---|---|
| E0 基线 | 固定前视短模板、两点输出、模型版本及同一完整episode回放；记录视觉编码/prefill/decode/头/控制时间 | 保存原始输出与完整时延分布；旧五点只作显式历史对照 |
| E1 异步快慢链 | 语义路线异步发布、按源位姿对齐裁剪；AE最新多方向观测；轨迹短前缀接管 | 记录语义年龄、轨迹衔接与实际命令，车辆不能为等待常规VLM更新而周期性停顿；失效时仍停车 |
| E2 工程复用 | 模型常驻、视觉/词表缓存、LoRA合并对照、异步I/O、预热、融合批处理 | 仅缓存确实相同的编码；有效mask和源时间不因缓存刷新重置；不盲复用跨请求KV |
| E3 后端精度 | FP16/BF16基线，再按收益试INT8/INT4和可用attention/推理后端 | 同时回归编号、两点、Route、Decoder和K/V；质量/接口失败则保留原精度，不静默回退 |
| E4 学习型压缩 | 历史/地图/多视图token池化或学习压缩，按模块单独训练 | 当前前视细节和小标牌不能先被压掉；新权重、缓存与训练版本；比较完整任务质量 |
| E5 推测解码 | decode占主导且输出足够长时评估EAGLE类方法 | 计入草稿计算/显存，核验最终接受序列对应REFLINE状态；收益不足则不引入 |

前视VLM与多方向AE可共享满足条件的图像编码结果，但不能假定不同编码器、裁剪、分辨率的特征可互换。增加视图主要增加视觉计算/融合和传输成本，不直接增加VLM文本decode token。量化和压缩后仍需重新验证源时间、轨迹有效长度与停车条件；异步调度减少等待，不消除推理时延。

### 4.4 持续运动、更新与安全

曲线跟踪和VLM异步执行。每条模型队列一个处理中任务＋一个最新等待任务，记录被替换请求；新有效结果按当前odom对齐并尽快接管，不等旧waypoint全部走完。前缀衔接检查位置、朝向、速度连续性；过期/错源/取消/新障碍触发独立停车，不以平滑视频替代命令日志。

参考线按源位姿变换并裁剪，`z_sem`不做刚体旋转。当前像素demo的5秒有效期、旧TEXT10秒/PREFILL3秒是不同实验配置，应各自冻结，不混写成统一部署安全阈值。阈值取决于速度、可见路线剩余长度和动态风险，必须在实测中验证。

大角度转弯可采用“停平移→原地转向→获得新可见通道→恢复平移”；这需要1.5节接口与扫掠检查。多方向AE已列为目标结构，真实覆盖、深度/激光融合与历史地图过期策略仍须实现验证；仅前向RGB的盲区不能通过训练承诺消失。
