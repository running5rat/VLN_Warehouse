## 1. Model Pipeline

### 1.1 目标结构与模块职责

<!-- diagram:overview -->

图 1：慢语义分支只读取前视图像与地图；快AE分支读取多方向当前观测。两点锚点、连续参考线和实际动作分别可追溯。

| 模块 | 职责与边界 | 当前状态 / 下一动作 |
|---|---|---|
| RGB-D / odom | 提供同帧深度、内外参和源位姿 | Isaac/Habitat 数据链可用；当前为理想仿真 odom，不是 IMU/VIO 能力验收 |
| 几何与语义地图 | 全部有效深度更新几何；选中实例经投影、关联后登记 | 持久化、恢复、异步 OCR 已有实现；身份准确率和实时门槛仍有缺口 |
| YOLO-E / OCR | 定位所有候选实例；识别文字并绑定最明确承载实例 | 仓库固定词表引擎与 R2R 室内词表分开；不得混用类别索引 |
| VLM | Landmark 选择、Local 关系定位、Route 进度和局部路线表达 | 基础 InternVL3-1B；新任务能力未完成正式训练验收 |
| Reference Decoder | 静态名义参考路线、有效长度；不是动态障碍最终动作 | `[32,2]` 路线接口已实现，正式质量未验收 |
| 上下文压缩 | 同次真实 K/V → `z_sem [16,512]` | 接口已存在；不能用零向量或教师特征代替部署语义 |
| FMAE | 多方向最新感知＋参考路线条件，生成平滑、可执行且响应动态障碍的候选 | 部署九模态接口已有；多相机接入、训练/缓存/部署一致性待实施 |
| Scorer / 控制 | 候选核验排序、短前缀执行、独立停车检查 | 规则 Scorer 对照可用；学习型评分尚未训练 |

密集路线与动作张量接口沿用旧v0.7：Reference Decoder 使用8个控制点、32个采样点及前缀mask；上下文压缩为16×512。FMAE首版为512维、3个共享Transformer block、8 heads，横向LEFT/CENTER/RIGHT × 纵向STOP-YIELD/FOLLOW/PROCEED，共九模态；每条30个XY点、0.1秒间隔、Euler 4步，单噪声样本输出形状 `[B,9,1,30,2]`。FOLLOW是沿参考路线跟进/调速，不等于任务层跟随行人。旧单候选训练路径不能因部署已有九模态前向就被认定为完成九模态训练接线。

全局目的地可能不在当前 RGB 内，保留在 Route 和历史语义地图中；当前可执行的局部路线必须遵守所选输出协议的可见性和执行边界。Local 是关系描述，不直接生成或修正定位 TF。跨帧几何对齐依靠 odom；真实机器人阶段需独立验证 odom 漂移和重定位。

#### 1.1.1 已确定的前视语义、多方向动作分工

| 分支 | 输入设计 | 不承担的职责 |
|---|---|---|
| VLM／Reference | 前视当前及历史RGB、前视检测叠图、此前提交的语义MapView、Route/Local及相对运动 | 不把每路相机都送入语言模型；前视限制不删除已有地图记忆 |
| AE | 当前前/左/右/后RGB特征、各视图时间/内外参/有效mask、局部几何、机器人状态、对齐参考线和z_sem | 不额外生成第二份Route，不依靠陈旧语义承担全部动态避障 |
| 几何与控制检查 | 可获得的深度／测距、odom、障碍更新时间与footprint | 多路RGB本身不等于已有可靠的米制全向距离 |

首版目标为四方向输入槽位；具体相机安装、视场重叠与帧率在部署配置中冻结，不能仅凭“四路”声称360度无盲区。保留前视RGB-D；侧后方采用深度或测距融合方案提供几何证据，真实硬件选型另行核验。各路独立编码，加方向、相机外参和时间信息，再由动作侧融合；不直接拼成长图，前视特征仅在预处理/编码器一致时共享。

参考线描述名义局部路线，AE处理新障碍并在有效指导范围内避让、减速或停车。高层没有看见侧方通道时，AE不能以“避障”名义自行更换任务路线；触发重新观察或VLM更新。新增视图需要对应训练数据、标定与时延测试，缺失视图用mask关闭，不能复制前视图伪装多方向。

R2R单前视数据继续用于语义/参考线训练；多方向AE在后续仿真采集与合格机器人数据上训练。单前视benchmark与多传感仓库配置分别评测，不混排成绩。

### 1.2 输入冻结：少描述元数据，保留真实证据

近期采用已有 `route_only` 标注约定：首帧 `Previous Route = 原始 instruction`，后续传入最近有效 Route；原始 instruction 永久保存在任务契约和审核侧，但不重复拼入这一实验的模型输入。保留原指令作为每轮输入的方式只做显式对照，不混入同一训练版本。

学生逻辑输入草案如下；实际落地前固定模板、图像顺序、尺寸和哈希，训练与部署使用同一版本：

```text
Previous Route: <all remaining steps, initialized from instruction on first request>
Previous Local: <latest valid landmark-relative description, or unknown>
Motion since previous Local (<age> s): x_m=<x>, y_m=<y>, yaw_rad=<yaw>
Current detectable categories: <same-frame mask-backed categories>
Completion evidence: <confirmed or unverified>

<image>Historical RGB, 3 seconds ago, if available</image>
<image>Historical RGB, 2 seconds ago, if available</image>
<image>Historical RGB, 1 second ago, if available</image>
<image>Current raw RGB</image>
<image>Current RGB with detector boxes and instance IDs</image>
<image>Previously committed semantic map in current source body frame</image>
```

- 当前给模型的是原 RGB 和检测框/ID 叠图；像素 mask 用于投影及审核。不能将叠图称为已输入逐像素分割图。
- MapView 使用历史已提交语义及当时可用几何，不输入最终完整地图，也不增加文字地标目录。
- 相对运动为 `inverse(T_odom_previous_local) @ T_odom_current`；当前车体在上一 Local 源车体系中的位姿，x 前、y 左、米，yaw 逆时针弧度。
- Local 超过 30 秒或 odom epoch 变化时失效。历史关系不能冒充当前可见事实。
- `Completion evidence` 必须来自可获得的完成核验。当前 R2R 没有完整到达证据的样本保持 `unverified`；不由末帧、空路线或目标隐藏坐标自动确认。程序侧完成核验缺失也是工程待办，不能全归因于模型。
- 不发送 Progress、详细执行事件表、Map landmarks 表、batch/image ID、哈希、版本及完整候选参数表。它们保存在审计侧。
- 教师可使用详细规则；学生 SYSTEM 要短，但字段含义和可用观测一致。短模板目前仍须接线、训练及自由生成验证，不能直接删掉现有规则就宣称已优化。

### 1.3 输出和递归提交

当前教师原始输出为三字段 JSON：

```json
{
  "landmark": ["sign"],
  "local": "By sign 01/4R, facing toward sign 02/4R.",
  "route": "Continue to the aisle end, turn left, then approach the extinguisher and stop."
}
```

这是格式示例，不是待写入数据集的答案。教师不输出 waypoint/ref_line，不读取未来轨迹。下一版本学生 TEXT 保留五标签，仅将Waypoint改为两个：

```text
<landmark>[categories]</landmark>
<local>landmark-relative position and heading, or unknown</local>
<Route>remaining navigation commands, or DONE</Route>
<waypoint>(u1,v1);(u2,v2)</waypoint>
<REFLINE>
```

| 字段 | 下一版本约定（代码迁移后启用） |
|---|---|
| Landmark | 最多 3 个当前检测类别；不生成 image_id，不将 OCR 编号拼入 category；类别准入不等于精确选择某一个实例 |
| Local | 英文，最多 **90 字符**；描述位置与朝向，有证据才引用编号；不能只抄场景描述冒充定位 |
| Route | 英文，最多 600 字符；只写剩余导航命令，保留未完成步骤、顺序、目标和最终停等；只凭观测与相对运动删除已完成部分 |
| DONE | 仅在完成证据 confirmed 且整个任务完成时使用；模型文本不直接解除执行器的核验职责 |
| Waypoint | 两个有序的前视RGB原图像素点 `[u,v]`，或 `[]`；近锚点在前、远锚点在后；禁止混合像素与米 |
| REFLINE | 查询 token；连续参考线由实际处理该 token 的 hidden state 解码，不是语言模型生成数组 |

归档版v0.7中的Local 80字符、每轮Instruction及旧Route JSON是历史约定；本版使用90字符、route-only、自然语言Route。落地时以具体运行配置与版本为准，统一学生/教师文档映射后冻结新版本。历史教师标点限制与`Inferred:`、`01/4R`存在冲突；新模板须明确支持这些必要字符，旧响应保留，不静默重写。

递归更新顺序：冻结输入 → 一次请求 → 保存原文 → 校验 → 原子提交 Route/Local/快照状态 → 对同源 mask/OCR 入图 → 下轮读取。坏帧隔离，继续使用最近有效状态并记录年龄；Map/Route/Local 不跨任务串用。合法 Route 可更新而该轮参考线不可执行，不能拼接上一轮旧参考线伪装一致快照。

`PREFILL_FOLLOW` 保留独立接口：处理查询，不生成文本、不更新 Route、不发布静态地标。当前静态 TEXT 数据不能复制为跟随监督。

| 下一版本 `rgb-pixel-waypoint-v2-two-anchor` | 两个原RGB像素锚点；真实 `<REFLINE>` Decoder输出车体系连续线 → FMAE → 控制 | 本版确定的目标接口，解析/训练/部署迁移待实施 |

像素协议要求可见地面的局部前缀，不将标牌上的点当成车辆目标。原图尺寸、缩放/裁剪、内参和外参必须可追溯；深度无效时拒绝，拟合段还须检查遮挡和通行。车头至最近可见点的近端盲区单独检查。仅“像素在图内”不证明路线可通行。

Waypoint是可解释的稀疏视觉锚点，ReferenceLine是密集路线；本轮不删除任一输出。REFLINE查询位于Waypoint之后，Decoder读取实际处理后的hidden state；不能用两个点的插值冒充Decoder结果。两个点不足以唯一确定弯曲路线，连续形状由参考线监督学习，并对自由生成时的锚点/路线一致性独立验收。

标签生成：从批准的密集参考线中取前视可见、同帧深度支持的连续局部前缀，按弧长选其中点与远端作为两个锚点，再投影到原RGB。保留原始密集轨迹、完整参考线候选与裁剪依据；模型局部参考线监督使用同一有效前缀。相机近端盲区保留单独几何检查，不能标为RGB可见。短线不足以产生两个可区分锚点时输出`[]`并记录无有效局部指导；不复制点凑数，也不据此认定任务完成。

迁移顺序：版本化schema与两点解析/约束 → 从原密集GT重新派生两点（不能截取旧五点前两点）→ 人工审核投影 → 训练/推理共用模板 → Decoder自由生成一致性 → 控制验收。原参考线仍为32点，动作仍为30步；减少的是文本锚点数，不是连续路线/动作的采样点数。旧五点协议通过显式适配保留，不静默改变其数值含义。

像素工程对照若仍使用拟合器，须针对两点重新检查起始朝向、曲率及碰撞；不能假定旧五点PCHIP配置直接适用。新生成的两点结果需重新实际闭环，不能沿用旧视频作为通过证据。

最新两任务 Codex 视频为既有轨迹回放：37 帧，24 帧非空投影通过、13 帧空点；24 帧控制诊断均被占据/未知检查拒绝。旧米制 demo 的实际运动不能证明新像素预测完成闭环。

### 1.5 原地旋转：最小接口补充，尚待实施

位置 waypoint 不包含 yaw；`[]` 目前不能区分停止、无路线和需要旋转。不能用画面外像素、横向虚假路径或隐藏世界路线补出转弯。

建议在像素 demo 新协议中增加 `motion`，或等价的独立朝向字段：

```json
{"waypoint": [], "motion": {"type": "rotate", "yaw_delta_deg": 90}}
```

`rotate` 以请求源朝向为基准，正值左转；执行器锁定一次目标朝向，根据 odom 扣除已转角，不每周期追加 90°。可选 `face_pixel` 表达朝向当前图像内某目标，利用相机视线方向求 yaw，而非把像素投影成驶入位置。`stop` 与无效输出要有独立状态。

落地顺序：版本化 schema/解析 → yaw-only 示范标签 → 角度与源时间测试 → 静止 Isaac 左/右转 → 旋转期间新 RGB 回流 → 新有效输出接管。旋转保持平移速度为零，检查车体旋转扫掠范围；前视不等于全向安全。缺少侧后方证据时停等或补看，不以“原地转动”承诺可完成全部避障任务。

这是近期讨论的**建议**，当前未接入训练/控制。正式 FMAE 的 XY-only 输出同样不能充分表示纯旋转；后续应评估 SE(2) 或独立 yaw 通道，不把原地转向数据误标为 STOP。

### 1.7 持久语义地图：保留的模块细节

#### 1.7.1 高频深度几何与 odom 对齐

深度来自同步 RGB-D。内参 K 将像素反投影到相机系，再通过相机—车体外参和源时刻 odom 转到子图；深度定义、米制尺度、坐标方向和地面高度必须登记。仅有内参不能确定车体 BEV。长期 VIO 计划融合视觉、轮速和 IMU；当前仿真采集使用理想 odom，不能称为已实现实机 VIO 或无漂移 SLAM。

几何融合保存三维/高度信息，需要时生成当前车体系 BEV，避免反复重采样整张二维地图。仅在平面运动假设成立时使用 SE(2)；俯仰/侧倾变化应先对齐三维点。自由、占用、未知分开，所有深度障碍参与几何处理，不依赖 VLM 是否选中。

RGB 看得到不代表深度确认了整片自由空间：深度缺失、射线稀疏、遮挡、量程和栅格化都会产生 unknown。投影到 RGB 的参考线只验证图像几何关系，不证明无障碍。地图参数随入口登记：持久语义体素为 5 cm；局部网格范围、分辨率、采样 stride 与历史窗口不可跨实验混用。

#### 1.7.2 低频语义添加：从候选到多实例 mask

v0.6 的“语言对象短语 → 提示分割”保留为可选接口。当前实时主路径先用固定词表 YOLO-E 生成全部候选，VLM 基于原图和叠图选择可登记类别，再逐实例验证入图。这样避免把 VLM 的类别同义改写直接当作分割失败；类别只能来自当前真实检测列表，未检测类别不能补造 mask。

固定词表为 sign、label、storage rack、door、pillar、fire extinguisher、electrical cabinet。部署对照为 YOLOE-v8s TensorRT FP16、640 输入、conf=0.25、原图大小 mask、max_det=100；达到上限记录可能截断。类别特征初始化一次，模型常驻。词表外建议仅诊断，不在线改写冻结引擎。

保留 `segment_instances()` 多实例接口和兼容单实例 `segment()`。同类多实例不得整类拒绝或只取最高置信度：每个实例保存类别、框、置信度、mask、来源和处理状态。类别数组放通该类全部候选，并不表示 VLM 已精确选中其中某个实例。通道尽头、路口序号、左右关系不强制产生 YOLO mask。

#### 1.7.3 Landmark 记录、文字证据与定位职责

元数据和事件写 SQLite；不可变 NPZ 保存三维点等数组。先完整落盘数组再提交元数据，来源文件带哈希；重复事件校验内容但不重复记证据。地图可保存、重启恢复、跨任务继续更新，不覆盖旧实验原图和已批准地图。

```text
LandmarkRecord {
  landmark_uid, source_submap, observation_ids[], category,
  geometry, visible_surface_center, uncertainty,
  orientation?, orientation_kind, symmetry,
  static_status, first_seen, last_seen,
  text_evidence[], identity_status, conflicts[],
  needs_reobservation, review_reasons[]
}
```

内部 UID、类别索引、检测批次实例 ID 和真实 OCR 编号分别存储。法向/主轴/朝向不可观测分开处理，不能给圆柱或只见一面货架强制赋唯一 yaw。新语义实例为 tentative；类别、VLM 选择、一次清晰编号或短时不动，都不授予永久静态锚点资格。

Local 仅提供关系描述与待验证候选，不生成 TF。机器人位姿来自 odom 和经验证的地图变换；没有几何定位证据时，Local 不能把“近 01/4R”转换成精确坐标。不同位置的同文本实例保持分离并标记重复编号。

#### 1.7.4 多地图配准、融合与同步

沿用 v0.6 的 SE(2)/SE(3) 子图配准设计。平面情况下最小化可信对应的位置残差及可观测朝向残差：

```text
E(R,t) = sum_i w_i * rho(||R p_i + t - q_i||^2)
       + lambda_o * sum_{i in O} w_i * rho(d_sym(R theta_i, phi_i)^2)
```

d_sym 按 2pi 有向朝向、pi 无向主轴或不可观测处理，未知朝向不进入第二项。名称/编号、类别、几何与相对结构共同产生候选；RANSAC 初值后验证残差、内点分布、第二优假设及占用一致性。理论最小对应数不等于工程验收条件，重复走廊应要求额外独立证据。

当前跨 epoch 或旧地图加载必须验证地图到当前 odom 的变换；部分入口要求显式重叠图像锚点。配准失败保留独立子图，不默认两个 episode 坐标相同。保存原始子图和约束，支持错误约束/地标撤销；完整回环位姿图优化和多机器人增量一致性仍待实施。

多机器人目标设计继续使用同一来源、子图、变换和版本机制。共享 observation 不重复计数；旧自由空间不能覆盖当前新占用。无重叠、多解和不同时间质量必须保留不确定性，不以共享地图存在代替定位。

#### 1.7.5 学习型 OCR、延迟绑定与后处理

当前文字路径采用 PP-OCRv5 mobile 检测/识别，独立 CPU 进程、4 线程，对采样源帧做一次共享文字检测和批量识别；不依赖固定颜色、牌子比例或编号正则。保留原分辨率裁剪，不先把 mask 外涂黑。文字框坐标还原到源 RGB，以包含关系和嵌套检查优先绑定最小明确承载实例；多解记录歧义，不复制到标牌和货架。

`attach_text_evidence()` 根据源哈希和父实例事件找到已成功入图记录，只追加文字证据/身份状态。支持同帧先无文字、后合法补充及 OCR/VLM 乱序；父事件拒绝、来源不符、重复或过期结果不重新增加几何观测。

身份证据要求至少三个不同源帧一致读数及至少两个视角支持；同帧重跑不增加独立证据。完整父字符串支持与残缺子字符串支持分开。原始读数永久保留，冲突不自动纠字；身份确认与静态确认分离。

当前可逆视图策略 `landmark-view-v2-substring`：合格读数规范化后，移除被其他读数连续包含的严格子串；仅剩一个父串时采用它。若剩多个互不包含读数，放弃该实例 OCR 标签登记，mask/几何仍保留。不能把此规则称为通用漏字纠错，亦不能拼接不同帧片段伪造编号。

普通无文字 storage rack 默认隐藏，有文字者保留 review；通用警示词可作为属性而非唯一身份。过滤是显示/检索视图，不删除原始地图，也不自动过滤灭火器等设施。输出 keep/hide/review、冲突及补看理由，供后续主动观测使用；当前不据此改变车辆轨迹。

Florence-2 与 YOLO-E + server OCR 的历史对照保留；Florence 为同模型多任务调用，不算“一次前向定位分割读字”。当前实时路径不静默调用它补救失败。

### 1.8 Reference Decoder与原子快照

#### 1.8.1 参考线网络结构

沿用 v0.6 的查询表示 → 路线特征 → 控制点/长度/置信头。输入为实际处理的 <REFLINE> 最终层 hidden vector；LayerNorm → Linear → SiLU 后分成控制点、有效长度分类和置信度分支，B 样条确定性采样到固定点数。

当前接口固定 8 个控制点、32 个参考点、三次 B 样条，参考头隐藏维度 256；长度为 0…32 类，生成前缀有效 mask，置信度输出不是未经校准的安全概率。参考线主要表达静态名义路线与任务意图，不承担动态避让的全部职责；长期阻断或路线语义变化可触发 TEXT 重路由。

新协议的两个像素Waypoint经同帧深度投影后，与连续线应表达同一路线。TEXT 输出 [] 而 Decoder 有有效线时标记不一致，不作为有效运动指导。当前诊断阈值为锚点到线 0.30 m、端点差 0.50 m，同时检查顺序、方向和有限数值；这些是工程检查参数，不是已达到的导航精度。PREFILL 没有文本锚点，不适用该项。

倒退 5 m 诊断保留后向方向与任务起点含义，不因不可见后方或 unknown 空间拒绝诊断线；但当前不发布物理倒车命令。静态示范提取路线不自动等于当前已观测可执行路径，标注和执行检查分开保存。

#### 1.8.2 新旧参考线坐标与 odom 对齐

T_odom_body 表示车体到同一 odom 坐标系的变换。旧源时刻参考线点到当前车体系为：

```text
p_body_now = inverse(T_odom_body_now) * T_odom_body_source * p_body_source
```

对齐后裁去已执行前缀；动作时间轨迹还须按真实经过时间裁剪/重采样。不同 odom epoch 不可直接套用此式。地图到 odom 变换只在几何验证后使用，回环导致地图跳变时重新验证受影响路线，不能把坐标跳变直接变成控制突跳。

#### 1.8.3 VLM 上下文压缩网络

K/V 取自同次推理的有效序列位置，展开 KV heads 后拼接；TEXT 可包括真实输入与已生成语义位置，PREFILL 不存在回答 token。查询压缩器为本次请求的特征压缩参数，不是上一帧记忆状态。

```text
selected K,V [B,S,2*n_kv*d_head]
  -> LayerNorm -> Linear(512) -> SiLU -> Linear(512)
16 learned queries [16,512]
  -> cross-attention to selected context + residual
  -> normalization / FFN + residual
z_sem [B,16,512]
```

z_sem 不进行刚体旋转；AE 额外接收语义年龄与相对位姿。H/K/V/K+V 和压缩/完整序列的收益继续保留为消融。当前采用 K+V 不意味着所有参考论文采用同一设计，也不能继承其耗时或精度。

### 1.9 多方向条件FlowMatchingActionExpert

#### 1.9.1 输入与 token 化

AE 的职责是依据当前环境将任务参考线转为更平滑、满足动力学并避让动态障碍的时间轨迹；不是重复生成高层 Route。静态路线和动态动作 GT 分开，动态局部绕行不自动改写名义路线。

| 条件 | 表示与编码 | 约束 |
| --- | --- | --- |
| 前/左/右/后当前RGB / 局部BEV | 共享或独立视觉编码、方向/外参/时间embedding、动作侧融合 | 多方向融合待实施；缺失视图明确mask，不复制前视；与VLM低频历史缓存区分 |
| 机器人状态 | v、omega、footprint、运动方向及有效性 | 使用当前实测值，不依赖是否发送到 VLM prompt |
| 对齐参考线 | x/y、弧长、切向、有效长度和置信度 | 当前车体系、名义路线身份和来源明确 |
| z_sem | 16×512，上下文投影及 TEXT/PREFILL 类型标记 | 不旋转；不可用时不能拿零向量冒充真实缓存 |
| 语义年龄/相对 TF | dt、dx、dy、sin(yaw)、cos(yaw) | 同一 epoch，包含排队和持有时间 |
| 上一计划剩余段 | 位置、剩余物理时间、有效 mask | 先对齐再裁前缀，不当作不可更改轨迹 |

#### 1.9.2 九模态空间

横向 LEFT / CENTER / RIGHT，与纵向 STOP-YIELD / FOLLOW / PROCEED 组成九模态。侧向定义相对于参考线或绕障通路，不只看车体系 y 正负；FOLLOW 是沿路线跟进/调速，不等于任务级跟随行人。

无障碍时多个模态可以等效，不强迫所有轨迹两两不同。单候选碰撞或优化失败不能推出整模态不可行；未观察/未核验模态保持 unknown。mode feasibility 只有校准后才参与软排序，不能覆盖硬安全检查。

#### 1.9.3 共享条件 Flow 主干

首版实现使用 512 hidden、3 个共享 Transformer blocks、8 heads。横/纵模态 embedding 与 Flow time 条件进入每个 block；轨迹 self-attention、条件 cross-attention、FFN 与残差保留。条件编码一次，九模态共享，不建立九套网络。

```text
current conditions -> encode once -> context C
Gaussian x0 [B,9,K,30,2] + physical-time embeddings
for tau in Euler solver steps:
    shared blocks(action tokens, context C, mode, tau)
    velocity field v_theta -> trajectory update
output candidates [B,9,K,30,2]
```

当前 H=30、dt_act=0.1 s、4 步 Euler、K=1，输出米制当前车体系轨迹。Flow 生成时间 tau 与物理时间 i*dt_act 不同。网络内部归一化尺度必须记录并在输出恢复单位；不能把归一化数值直接用于控制。

原单候选 FlowActionExpert、QueryActionExpert 和旧训练配置继续兼容，不能复制一条旧轨迹冒充九模态监督，也不把旧 smoke checkpoint 当成已训练九模态导航权重。

#### 1.9.4 多模态与模式坍缩

保留 v0.6 的共享主干优先策略：先通过有效模态平衡、同场景多策略示范与条件响应验证区分模式；确认存在条件忽略或梯度冲突后才引入横向/纵向轻量 Adapter。不能用多样性损失强迫安全性更差的轨迹。

在确有多种可行绕行/停等策略的场景固定观测、噪声改变模态，比较行为响应、可行覆盖和拒绝原因；开阔区域轨迹相似不是塌缩证据。模型头已接通不等于这些学习目标已实现。

#### 1.9.5 倒车、跟踪和有效性

长期设计需显式有符号速度/运动方向以区分倒车与转身前进，XY 单独不足以表达纯原地转向。当前物理倒车关闭，后向线路只诊断；纯旋转片段保留 yaw 和控制证据，不当作完整 XY 动作正例。

候选在生成完成及执行前重新对齐当前车体、检查年龄、footprint、速度/加速度/转向和当前占用。前向相机不保证全向安全：转弯应检查机器人扫掠区域、近期观测的有效性与盲区；原地转向是可选观测动作，不是自动获得全向无碰撞保证。超时或缺乏足够可执行证据应停等。

### 1.10 Scorer与候选选择

#### 1.10.1 候选编码与当前规则对照

沿用“先硬过滤，再排序”的分工。硬过滤检查有限数值、时间/版本、时变占用、footprint、速度、加速度及转向执行性。safe_mask 为空时独立制动/等待，不把 STOP-YIELD 名称视为停车安全证明。

当前使用规则 Scorer：对合法候选按路线进展、偏离和平滑性排序，固定顺序处理同分。学习型候选编码、可行性头及 Hydra-MDP 式评分训练仍为后续研究，不因为已存在规则分数就宣称学习型 Scorer 已验收。

长期候选编码输入 x/y/t、速度/曲率、参考线偏移，经 MLP、时序 attention/pooling 与共享场景 cross-attention，显式读取具体候选；场景编码器共享当前图像/动态 BEV、状态和参考线。

#### 1.10.2 并行评价头与 Mode Selector

Candidate Scorer 输出 q[m,j] 及安全、进展、舒适等分项；mode feasibility 对九个模态 query 输出 f[m]。两头功能不同、并行输出，不循环互相调用。

```text
j*(m) = argmax_{j: safe_mask[m,j]} q[m,j]
s[m]  = q[m,j*(m)] + lambda_f * log(max(f[m], epsilon))
m*    = argmax_m s[m]
```

没有安全候选的模态 s=-infinity。可行性尚未校准时 lambda_f=0 且不计算 log 项；f 只作软先验，不整类硬删除，也不能使已拒绝候选重新入选。返回具体带时间轨迹，不只返回模式名。

#### 1.10.3 执行、回退与生命周期

候选选择后仍接受新障碍和来源年龄检查。控制器只执行可替换短前缀，后续感知/规划可替换；无合法轨迹时停车。传统局部规划回退只能在明确标记的独立后端使用，不能伪装成模型候选。

每次生成器更新后重建实际候选分布与 Scorer 校准数据。ScorerOracle 评价候选，不创造专家轨迹；动态优化器返回数组也不自动代表有效 GT。保留候选级失败，模态未知与负例分别处理。

### 1.11 控制器与独立执行检查

#### 1.11.1 轨迹跟踪接口

输入为当前车体系带物理时间的轨迹、运动方向、有效期和最新机器人状态，输出差速底盘 v/omega 或轮速。当前工程控制使用带速度前馈的 Pure Pursuit；MPC、AL-iLQR 保留为可比较控制方案，不与用于离线生成 GT 的 Oracle 混为同一个模块。

当前低速联调最大线速度 0.3 m/s、行人示例 0.2 m/s、跟随距离 1.5 m，均为运行配置而非普适部署能力。不能沿用旧训练配置中更高的默认速度作为实际车体约束。

#### 1.11.2 独立安全执行

控制与 watchdog 独立于 VLM/OCR：检查命令超期、感知年龄、任务取消、新障碍、epoch 跳变和运动弧线。失去有效指导或未知风险超出已验证条件时停等。物理步进 60 Hz、命令检查目标 30 Hz 为当前设置，实际周期须在并发负载中测量。

人类遥操作采集的探索策略可以允许驾驶者进入未知区域；该特例不得静默用于自动导航。参考线诊断、候选几何可行和实际安全执行是不同层次。不能因 2D 画面中线路可见就跳过深度/footprint 检查。

#### 1.11.3 结束与任务连续性

DONE 为模型声明；程序结合任务定义核验目标可见、距离/区域到达与实测停车等证据。人工 warehouse demo 约定目标 4 m 内只用于该基准，不能套用官方 R2R/RxR 判据。任务取消、超时、预算耗尽和成功分开记录。

PERSON_FOLLOW 默认持续直到取消/显式终止；接近目标可等待，目标丢失不算任务完成。相同子目标只改变措辞不应重置运动起点，紧凑 Route 不含稳定 clause_id 时仍需明确该能力的工程限制，不能宣称已解决任意任务计数。

精确停靠、取货与多机器人调度不属当前验收。安全层规则的存在不证明真实世界安全性；实机需要制动、载荷、盲区和时钟标定的独立测试。

### 1.12 任务与执行后端边界

新入口只要求自然语言 instruction，人工不拆解子任务。原 GOAL / INSTRUCTION / RELATIVE_MOTION / PERSON_FOLLOW 保留为任务概念，旧 `--task-mode` 保留为兼容配置，与新 `--instruction` 互斥。

| 任务 | 输入与目标 | 当前边界 |
| --- | --- | --- |
| 地标/对象导航 | 前往已观测标牌或设施旁的可通行邻域 | 目标不在当前 RGB 内时可利用历史语义地图；零匹配或重复编号不强行选一个 |
| 路线指令 | 按自然语言顺序经过通道、路口和转向 | Route 表达剩余动作；短协议不再生成供程序分派的子目标 JSON |
| 前沿探索 | 基于已观测自由/未知边界选择可达前沿 | 几何对照独立保存，不读取隐藏全图或 Oracle 路线 |
| 相对运动 | 例如沿任务起点后方延伸 5 m | 当前倒退只做参考线诊断，不物理倒车；长期支持需后向感知与控制验证 |
| 单人跟随 | 目标绑定后使用当前观测位置生成滚动参考线 | 单人短时绑定/重确认；丢失停车，不自动换人 |

执行后端明确分为：`reference-only` 只推理/显示、不驱动车辆；`geometry-baseline` 用已观测地图进行工程规划；`model` 执行通过检查的 Flow 候选，无有效候选则停车。不得在 model 失败时静默切换几何对照，也不得把工程路径写成模型预测。

新 compact Route 不再包含 action/status，几何执行器不能从它自动获得旧子目标枚举。旧结构化 Route 及明确 task-mode 可继续服务工程对照；通用自由语言到所有专用执行模式的路由能力仍是缺口，不能以字符串关键词规则伪装成 VLM 理解。

## 2. Training Schedule

### 2.1 当前训练基础与限制

人工 `manual-static-004` 的 10 个批准关键帧已完成一次 100 步训练链路诊断：文本/参考线 loss 下降、冻结检查、严格重载通过。它是同 episode 拟合，不是泛化成绩，诊断 checkpoint 不作为正式实验初始化。

当前默认是语言全部层 Q/K/V/O 的 **r=16** LoRA；最近讨论的全部层 Q/V **r=8** 尚未切换。若作为低成本实验采用 r=8，需配置化 target_modules，记录实际匹配层数与参数数目，检查保存/部署严格重载。基础模型及视觉编码器冻结，Reference Decoder 单独训练。约 54 万 Q/V LoRA 参数只是依据本地结构计算的规模，不包括 Decoder，也不决定“最佳数据量”。

TIC-VLA 原论文采用冻结视觉编码器的语言侧全参数 SFT，不是 r=8 LoRA；其硬件、数据量不能直接作为本项目最低要求。既有 10 帧诊断日志的 PyTorch 峰值分配约 4.64 GiB、稳态优化器步约 1.11 s，仅属于旧 r=16 输入与小样本环境。正式 R2R 应先测 100–300 步，再估算时间；不将其机械外推作为工期承诺。

#### 2.2.1 更新参数、比较方法和升级门槛

- 语义阶段：仅语言LoRA和**整个Reference Decoder**更新；基础视觉/语言权重冻结，动作头、Scorer和未使用的上下文压缩器不更新。记录匹配模块、参数量和梯度，不能将“完整训练Decoder”误称“完整训练VLM”。
- 秩对照：固定target_modules、alpha/r缩放、数据顺序、有效batch、训练样本曝光量和评测；允许同等小预算选学习率并单独记录。保留r=16现有基线。r=8 Q/V作为另一个低成本对照，不能据它与r=16 Q/K/V/O的差异推断纯秩效应。
- 容量对照：优先同系列1B/2B；4B级模型若更换骨干/预训练数据，明确为模型选择而非纯容量消融。比较真实生成、递归Route保持、参考线、闭环指标及端到端p95，不只比较loss或参数量。
- 全量升级门槛：批准数据和修订链可重建；独立布局/建筑划分无泄漏；LoRA在合理调参后仍显示欠拟合或规模收益趋缓；能够承担显存和训练时间。若训练拟合好但验证差，先处理过拟合、场景覆盖和标签问题。
- 单卡4090先做100–300步资源预检；显存包含图像token、激活、优化器、Decoder及并发模型。不得以“LoRA参数少”保证4B多图输入一定能装入24GB；先冻结输入预算再测量。
- Stage2冻结选定VLM与Decoder，训练FMAE、动作侧多视图融合、投影和上下文压缩器；导出该语义checkpoint真实压缩前K/V并注入时延/位姿差。旧单前视动作数据保留缺视图mask，不伪造四路观测。

### 2.3 数据配方与实验控制

Stage1a 第一轮采用 **100% 合格 R2R 导航监督**，先回答 R2R 上是否有效。人工基准默认用于回归，只有明确标记的有限拟合诊断允许更新参数；4 个比较任务也不自动入训练。

首轮试验配比以**采样后的有效训练样本数**为分母，不按库存帧数、视频小时或磁盘大小计算。先选数据池，再在池内按任务/episode/关键事件采样，长视频不因重复帧自动获得更高权重。以下是已纳入计划的起始试验配方，不是已经验证最优的结论：

| 阶段 | 起始采样配方 | 对照与条件 |
|---|---|---|
| Stage1a初始 | 100%批准R2R | 先确认导航与中间监督有效 |
| Stage1a扩展 | R2R 72%＋英语RxR 18%＋空间/指代VQA 10% | 导航子池内部80:20；做辅助VQA 0/10/20%对照，导航部分同比缩放 |
| Stage1b仓库 | 仓库50%＋R2R/RxR保持池40%＋针对性VQA 10% | 对照仓库适应与benchmark遗忘；仓库池内部先约20%恢复/纠正样本，即总量约10%，不是额外加20% |
| Stage2动作（暂缓） | 动态仿真机器人60%＋合格真实机器人30%＋可适配人类轨迹最多10% | 人类数据不合格则关闭该池，并将其额度按2:1分回前两池；不为凑比例伪造尺度/深度/视图 |
| Stage3评分（暂缓） | 按候选风险、失败类型和已核验模态分层 | 无统一文本/动作混比；unknown不作为不可行负例，保留部署分布评估集 |

VQA优先补地标指代、地图与RGB关系、相对方向、历史/当前区分、任务剩余步骤和到达证据；不要求每个VQA都带轨迹，无几何标签关闭相应loss。冻结VLM后的Stage2中，普通VQA不再能通过文本loss改善被冻结的语义模块，不机械沿用Stage1配比。

参考经验：[LightNav-0](https://www.lightorigins.com/en/blog/lightnav-0)第一阶段Pointing/单图VQA/通用视觉及抽象推理/视频推理采样约35.14/25.05/20/19.81%，第二阶段导航动作/VQA为77.6/22.4%；[ABot-N0](https://arxiv.org/html/2602.11598v1#S4)动作与语义联合训练阶段保留约20%推理回放。本项目动作阶段冻结VLM，训练边界不同，不能直接照搬比例。辅助样本成本与梯度占比另行记录，样本比例不等于token或loss比例。

旧文档的仓库70%/外部20%/辅助10%是历史候选，本版首轮仓库配方使用上表50/40/10。真实仓库先以完整任务、路线和关键事件覆盖确定采集量，试采后换算小时，不凭仿真帧数承诺最低录制时长。

每个实验遵守：先采来源/任务，再采 episode/事件；同路线不同指令按组划分；不要通过增加直行重复帧掩盖转弯、停止、重定位和地图依赖样本不足。静态名义路线与动态避让动作不互换标签。

### 2.4 损失、数据量与评测

静态阶段：有效答案token的masked CE（包含两点像素文本），加车体系参考线点、有效长度和有效性监督；两点投影一致性作为独立诊断，几何辅助loss仅在有效投影时启用并记录权重。缺失动作loss为零。未标注路线、明确空路线、有效短路线分别编码。参考线不因文本点数变为2点。

以本地 R2R 120,930 关键帧 / 10,819 任务估算：300 任务约 3,400 个时刻，1,000 约 1.1 万，2,000–3,000 约 2.2–3.4 万。它们是多图上下文训练样本，不是独立场景数；正式导出按实际审核数量统计。没有依据将 r=8 对应成一个固定最佳数据量。

| 验收层 | 检查方式 | 进入下一步的条件 |
|---|---|---|
| 数据/接口 | 来源、坐标、监督 mask、严格重载、冻结梯度 | 确定性检查全部通过；批准样本可完整加载；未标注分支不贡献 loss |
| 拟合 | 同样本 loss、真实自由生成、Decoder 原始数组 | loss 有限且下降；存在真实合法完整输出；不能用强制模板结果代替内容学习 |
| 语义 | 完整 episode 的 Landmark、Local、剩余步骤、错误 STOP/DONE | 对比未训练模型并报告分母与修订量；路线遗漏等关键错误不能因格式通过而忽略 |
| 路线 | 可见/可投影性、米制误差、有效长度、方向、锚点一致性 | 分开报告 teacher-forced 与自由生成；正确方向和有效运动正例不能全为零 |
| 导航 | 固定执行器闭环 SR、SPL、NE、轨迹遵循及停止 | 按对应 benchmark 官方判据；失败/停车全部计入；报告不确定性，不能只展示成功视频 |
| 扩量收益 | 300/1,000/3,000 嵌套数据规模实验 | 验证集改善时扩量；拟合/标签/接口出错时先定位原因，非自动增加 API 用量 |

内部开发数据按建筑/路线组留出；官方 val_unseen 用于约定频次的模型选择，test 不用于调参或生成训练标签。最终主要对照建议至少 3 个 seed，报告均值与波动；先用单 seed 做低成本排错，不将其包装成稳定收益。官方协议与本系统 RGB-D＋理想 odom 的扩展设定分别列出，不混排分数。

以下是**顺序安排和初步工作量估计**，不是已批准的自动训练/消费计划。以一条主要开发线、单张 4090、审核人员及时反馈为假设，人工审核与模型运行等待另计；没有通过关卡就调整日程，不带失败进入下一阶段。

| P1 | 前视短模板、两点投影标签/协议迁移、LoRA目标模块配置 | 按M1预检重估，旧2–3日不作承诺 | M1、A0配置与测试；旧五点兼容；像素/米制不混用 |

优先级：正确的训练标签与协议 > 有效闭环基线 > 扩量 > 推理压缩 > 动态系统。实现负责人承担数据/模型/部署接线；人工审核人负责标签批准及任务标准确认。无人审核时应交候选报告，不把 machine-generated 状态改为 approved。

### 2.6 后续动作、评分与闭环训练细节（暂缓）

#### 2.6.1 动态动作GT与Flow Matching

动态监督优先同静态任务/布局配对，增加行人横穿停等、局部阻挡绕行、解除后恢复三个最小试验。名义静态参考线不变但随当前 odom 对齐；永久封路改变任务路线另标重规划，不把每次动态绕行污染路线 GT。

Oracle 分工：Lattice 产生侧向/纵向初值；官方 ALTRO 的增广拉格朗日 iLQR 能力在隔离环境优化；ScorerOracle 独立验证/评分；人工可提供额外示范但标明来源。动态预测只用当前/历史观测的位置、速度、不确定性；未来动态真值仅用于独立核验，不进入求解器在线条件、VLM 或 AE 输入。本条替代 v0.6 中可能将未来动态真值用于 Oracle 的宽泛表述。

优化状态包含 x/y/yaw/v/omega，按当前差速低速配置约束，输出采样为 H=30、dt=0.1 s 的 XY 动作标签，并保留原 yaw、控制和物理时间。固定回放行人的非交互假设明确记录。至少等待/减速、绕行和恢复各有真实可执行正例，需通过 Isaac 控制器执行，不只验返回数组。

外部机器人/人类运动数据先审计尺度、时间、身体/相机坐标、外参及机器人可执行性。头部摆动、侧移和纯旋转单独处理；机器人化变换另存来源并重新验证，不能仍称原专家执行。缺可靠参考线的动态轨迹不反推名义路线；一条示范仅支持其所属模态，其余 unknown。

条件 Flow Matching 采用合法示范和有效时间点：

```text
x_tau = (1 - tau) * x_noise + tau * x_expert
target_velocity = x_expert - x_noise
L_FM = masked_mean(||v_theta(x_tau, tau, C, mode) - target_velocity||^2)
```

只对可追溯有效模态计算，未知模态无轨迹 loss，不作为负例。可加入低权重动力学/侧向/停等一致性项，但需独立消融。冻结 VLM/Decoder，训练 Flow、压缩器和动作投影；缓存来自真实冻结模型的压缩前 K/V，绑定输入/地图/模型版本。

延迟条件覆盖实测排队、计算、传输和持有时间，分别保存 GT、预测和延迟对齐参考线。Flow 准确性、候选可行性与控制跟踪分别报告，不能仅以离线轨迹误差认定闭环安全。

#### 2.6.2 ScorerOracle与学习型评分

ScorerOracle 对具体候选独立计算静态/动态碰撞、动力学、TTC/安全距离、参考线偏离、进展、平滑、效率及可用的社会通行项。硬约束失败不得成为动作正例；分项、拒绝原因和核验来源全部保存。

训练先采用宽分布 Lattice/Oracle 候选，再冻结当前 Flow 产生实际候选校准。只在明确偏好时计算 pairwise ranking；分项回归用于诊断；模态标签 positive/negative/unknown，BCE 仅用于已知项，允许多正类。碰撞候选是候选负例，求解失败不是整模态负例。

```text
L_scorer = lambda_s * masked_score_regression
         + lambda_r * ranking_loss_on_verified_pairs
         + lambda_f * BCE_on_known_mode_labels
```

学习型 Scorer 不反传更新生成器；Flow 更新后刷新候选、评分与校准，保留历史难负例但覆盖当前分布。Hydra-MDP 等作为候选评分流程参考，不直接移植车规平台的任务指标、动力学或数据规模作为本项目验收标准。

#### 2.6.3 闭环DAgger与交替更新

只在训练布局收集偏航、近碰撞、停滞、旧参考线、模态犹豫和目标丢失状态，记录策略提议、实际执行、Shield 干预和版本。独立 Oracle 无解时保持 unknown；审核去重后与初始有效数据按来源/模态/困难事件混采。

更新顺序为 Flow 训练 → 冻结 Flow → 新候选与独立评分 → Scorer 校准。初期慢语义分支冻结；若根因在 Landmark/Route，另行修复并重新导出缓存。验证/测试轨迹不得回流训练。DAgger 是数据聚合，不是新 loss，也不等同于 RL；选择性查询不自动继承全查询保证。

#### 2.6.4 可选动作侧RL

保留 v0.6 的启用条件：先有稳定 IL/DAgger 和明确瓶颈，再考虑动作侧 RL。必须定义随机策略变量、概率或可用代理目标、奖励、更新边界与预算；Flow 初始噪声概率不是最终选中轨迹的概率，不能把 solver 和 Scorer 选择直接套入 PPO 比率。

可比较 Flow 兼容的随机探索/GRPO 或显式动作策略，但改变接口需单独记录。Scorer 不能替代生成器产生缺失策略，RL 也不能修复所有高层标签错误。EAGLE、量化、推理后端和缓存优化仅作候选，修改后重测语义、参考线和端到端时延。

### 2.7 对照验收与误差定位

每个checkpoint使用同一套完整任务，分别记录教师强制输入下的训练诊断、自由生成下的语义/参考线结果，以及真实闭环表现。三种结果不能混为一个pipeline成功率。先检查错误来源，再决定扩数据、改骨干或增加优化。

| 观察到的问题 | 优先排查 | 不应直接得出的结论 |
| --- | --- | --- |
| 训练loss不下降或头无梯度 | 监督mask、源坐标、查询状态、冻结边界、优化器 | 数据太少或模型太小 |
| 拟合好但未见建筑明显退化 | 同源泄漏、布局覆盖、过拟合、教师标签偏差 | 加大LoRA秩必然改善 |
| Route漏步骤或提前DONE | 原始任务保持、历史递归、完成证据、标签修订链 | 格式合法就可批准训练 |
| 两点合法但参考线冲突 | 同路线GT、像素投影、Decoder自由生成条件分布 | 两点插值可以替代真实Decoder验收 |
| 路线正确但动作碰撞/停滞 | 最新多视图、时延、动力学、候选与控制跟踪 | 应直接重训语义VLM |

最小批准链：数据与协议测试 → 有效梯度和严格重载 → 真实自由生成正例 → 固定布局/建筑留出评估 → 资源与时延报告。扩大训练规模、解冻语言主干、开启动作训练分别有独立关卡；任何阶段失败不得通过人工替换输出补成成功。

### 3.2 固定数据格式与因果边界

沿用 schema v2，不重设计基础容器：

| 命名空间 | 内容 | 约束 |
|---|---|---|
| observation | 图像、历史地图、标定/位姿、任务契约、旧Route/Local、可测事实 | 通过白名单形成prompt；不把整个JSON发送给模型 |
| supervision | 批准文本、参考线/锚点、未来扩展的动作/评分及有效mask | 不能进入教师或学生的观测；缺失不补零标签 |
| provenance | 来源、任务/路线组、布局、协议、模型/标注人、哈希、批准/修订记录 | 不作为模型身份特征；用于去重、审计和复现 |

保留原始yaw、速度、控制和时间轴；纯原地转向没有XY进展不等于停止。R2R回放时间是仿真时间，odom是理想局部位姿，不伪装成真实IMU。

参考线为`[32,2]`、有效前缀mask、0.25m默认弧长间距；旧版五锚点保持原协议。新版本从同一批准路线的可见前缀重新派生两个像素锚点，另存`[u,v]`、原图尺寸、可见性、投影来源和对应几何，不能覆盖旧字段含义。动态绕行不作为静态名义路线GT。

多方向数据在observation中按视图保存RGB、可用深度、时间戳、内外参及有效性；前视VLM输入白名单不自动纳入侧后相机。未来轨迹和隐藏几何继续留在supervision／核验侧，不能通过多视图或地图缓存泄漏。

### 3.4 审核内容与递归修订

整episode展示所有预定关键帧，遵循 [Agent.md](Agent.md)：实际RGB/检测图、输入地图、Previous Route/Local/运动、真实prompt及原文、输出字段、示范几何GT、投影/地图状态、来源与时间。

人工重点分六类判断：

1. 当前Landmark是否有同帧实例，是否值得登记；不是仅看类别名匹配。
2. Local位置和朝向是否有RGB/地图支持；OCR冲突、历史推断是否标明。
3. Route是否保留全部未完成步骤、最终目标和停等；是否误把场景描述写进路径。
4. STOP/DONE是否提前、是否停止后又无依据增加动作；记录Completion证据缺口。
5. 地图、OCR归属与实例关联是否错误传播；tentative不等于可靠静态锚点。
6. 几何GT是否同源、可追溯，是否有参考线覆盖缺口；未知空间诊断和实际控制检查分开。

121个规则失败帧全部复核；其余合法帧按整段任务审核，优先转向、目标出现、停止、地图依赖以及历史失败后恢复帧。没有逐字段审核的合法帧仍为候选，不自动设为approved。

人工修订单独存储，原始模型递归链保持原样。若将修订用于训练，重建该版本后续Previous Route/Local；若Landmark选择改变，应重放对应语义地图并复核后续输入。仅替换答案而继续用旧错误地图/历史作为“已修正链”不可接受。不能把这份人工修订链冒充模型原始闭环成绩。

### 3.7 一个重建场景生成多个任务：轨迹Oracle的最小职责

<!-- diagram:engine -->

图 7：任务需要匹配的轨迹来源。几何监督与语义教师分别产生标签，在核验和人工审核后汇合；未来轨迹不进入教师观测。

**新生成任务没有现成示范轨迹时，需要轨迹Oracle或人工示范。** 仅重写同一已核验路线的指令、从原示范中切取合法子任务时，可以复用已有轨迹，不必重新规划。重建场景提供可观察环境，不能自动提供任务对应的正确动作。

| 数据情况 | 路线来源 | 是否需要新轨迹Oracle |
|---|---|---|
| 同轨迹指令改写／合法子段 | 已核验专家轨迹，重新核对起终点与指令范围 | 不一定；保留来源并按同路线组去重 |
| 新起点、目标、路线顺序或绕行条件 | 静态几何规划＋控制回放，或人工驾驶 | 需要；不能把别的任务轨迹直接配给新指令 |
| 添加行人/车辆后的动态任务 | 动态规划Oracle或人工示范＋独立核验 | 后续动作阶段需要；本轮不提前启用AL-iLQR |

最小静态引擎：

```text
场景采集/重建或既有USD资产
→ 米制尺度、碰撞网格、可通行区域、标定及目标身份核验
→ 先按布局族划分train/dev/test
→ 采样起点/朝向、目标可停邻域、必要的有序途经条件
→ NavMesh或占用图搜索（如A*）生成任务一致的路线
→ 差速控制器在仿真中执行、记录实际轨迹与碰撞/到达结果
→ 任务核验通过后提取静态参考线与两个可见像素锚点
→ 因果RGB-D/地图/历史 → 语义教师 → 递归审核 → 批准导出
```

多步指令必须逐个满足途经条件，不能只规划起点到终点最短路后声称完成“第二路口右转”等要求。对于新合成任务，可先生成可执行路线与途经事件，再生成匹配指令；对于既定用户指令，则先明确可核验的任务约束，歧义任务进入隔离池。运行时仍只输入instruction/剩余Route，生成侧任务条件和全局真值不进入学生观测。

静态Oracle无需先实现AL-iLQR；几何路线必须经robot footprint、转向可执行性、目标停留邻域和实际控制回放核验，平滑后再次检查。存在漂亮渲染但没有可靠尺度、碰撞或深度的3DGS场景，不直接作为米制动作GT。失败路线/碰撞执行归档，不标为成功专家。

语义Oracle与轨迹Oracle分工：教师只根据当时可用输入生成Landmark/Local/Route；几何GT由示范/规划执行产生。核验器可使用隐藏几何和未来轨迹检查一致性，但不能把这些信息灌入教师的Local或学生输入。参考线保持静态名义路线；动态避让另外标动作，不覆盖静态路线。

增加偏离路线、错过路口、朝向误差、相似编号、局部地图/OCR冲突等纠正样本，从扰动后的真实观测重新求解剩余任务，不沿用原状态答案；任务内历史不可能获知的完成步骤不能凭空补入。一个场景生成很多任务不能代替布局多样性，所有同布局变体/配对动态任务/重叠轨迹按组隔离。

可借鉴[ABot-N0 Data Engine](https://arxiv.org/html/2602.11598v1#S3)的导航图、规划与示范混合、偏离恢复样本和推理/轨迹一致性核验；不复制其规模作为本项目采集指标。近期先在现有仓库验证少量新起终点和多步任务，生成—执行—核验通过后再批量化。

### 3.8 人工采集与完整episode审核

一个 episode 是一个完整场景任务。先走查真实可行任务，例如沿通道到尽头左转、再到可见灭火器旁；不强求最初“两次转弯”的示例，也不移动物体迎合指令。原场景与起点更换后重新核验。

通过浏览器遥操作：启动传感和地图 → 开始录制 → W/A/D 或方向键驾驶 → 标记实际转向、目标可见、停止、到达 → 结束并离线回放 → 审核关键帧文本和路线 → 批准整段。失焦/超期停车。保存人工请求命令和实际执行/干预，不把发出停止命令当已停止事实。

默认约 10 个关键时刻，事件可追加；不逐 RGB 帧强制标注。候选路线从后续实际示范轨迹提取，去重停顿、变换到源车体系，再人工修正抖动/切角并复核障碍。保存原始轨迹、自动候选、人工修订和批准版本。RGB 投影辅助不检查全部遮挡，不能作为通行证明。

人工可看未来示范以审核路线，但不能在早期 Local/Landmark/Route 标签加入当时无法知道的事实。暂停/恢复轨迹不拼成连续 GT；修改上游 Route 要重新审下游依赖。任务终止事件需真实记录，缺失时保留待核验，不补造时间戳。

按 Agent.md，以完整 episode 展示全部预定关键帧：原始/历史 RGB、模型实际检测叠图、实际输入地图、instruction、旧 Route/Local/相对运动、完整 SYSTEM/USER、原始输出和解析结果。单独展示模型未看到的 mask、未来轨迹、完整位姿/事件/地标表等审计辅助。

教师评测只评 Landmark/Local/Route，waypoint 标“非教师生成”；系统 TEXT 则必须展示真实 waypoint、Decoder 原始数组/mask/置信度和 BEV/RGB 投影。一个 episode 一个视频，在对应源帧更新文本；稀疏帧只能称幻灯片，不伪造连续运动。按源时间离线回放不能证明在线延迟。

逐字段 verdict 为 pass/partial/fail/unscorable/not_applicable，未审核为 review_pending。模型返回、格式有效、语义通过、批准标签四种数量分开；未运行/错误引用/截断保留在固定分母。会话辅助视觉复核不冒充人工批准。

报告需展示错误首次出现和传播、改善/退化及证据。对 detector miss、无 mask、OCR 错字、载体错绑、投影/关联拒绝、Local 幻觉、Route 丢目标分别归因。身份尚未确认不等于已检测物体不存在，后处理采用父字符串不等于 OCR 模型准确率提升。

### 3.9 输入、标签与审计工件

每帧保存实际SYSTEM/USER、图像顺序与哈希、输入地图、Previous Route/Local、教师原文、解析结果、几何GT、模型输出与批准版本。两个像素锚点与参考线由轨迹派生，不写入教师输入。短线、无有效路线、未标注分别编码；纯旋转保留yaw与控制，不伪造成停车标签。schema v2容器不变，新增协议版本、view有效性、投影来源与监督mask。

模型返回、格式通过、逐字段语义通过和人工批准分别统计；恢复请求的attempt数与源帧数分开。修订上游Route/Local或Landmark后重建下游上下文和受影响地图；原始模型闭环保留不变。

## 4. Deployment Optimization

### 4.1 部署路线与运行边界

第一落点是单张 RTX 4090 工作站＋宿主 `/data/isaacsim` Isaac Sim 5.0；离线训练/教师和感知分别使用隔离环境。宿主启动桥接沿用现有脚本，不升级 Isaac 内置依赖来兼容推理库。Orin NX 是后续独立部署目标，PC耗时不能当端侧验收。

近期推理分工：几何不等待模型；YOLO-E常驻、固定词表特征初始化一次；OCR独立低频队列；一个VLM服务串行处理TEXT/PREFILL，任务内不并发更新递归状态。模型结果通过来源/版本检查发布，地图保持单一写入者。

新设计将多方向图像留在快AE分支：VLM/Reference保持前视图像预算和地图输入；AE对多视图进行有界融合，检测/测距与控制不等待文字生成。传感器掉线或时延过大时保留无效标记，执行范围依据可用观测收缩，不静默退成“完整全向感知”。新增相机、编码和仿真渲染的GPU竞争单独测量。

导航模式只执行一次完整TEXT，不额外再跑一次自由物体问答或实例筛选VLM。独立建图模式可仅生成Landmark；模式变化必须记录实际prompt及分支，不把两次推理统计成一次。

### 4.2 性能目标与测量口径

| 链路 | 沿用目标 | 验收口径 |
|---|---|---|
| 物理步进 | 60 Hz | 仿真步长；不与RGB采集频率混淆 |
| RGB-D / 几何 / 候选分割 | 5 Hz，运动期间实际至少4.75 Hz | 真正处理的不同源帧；几何完整消费；替换/超时计入 |
| 多方向AE观测与融合 | 首版与Flow 5 Hz目标对齐 | 逐路源时间、同步误差、缺帧和新鲜度；不能把4路合计20帧/s称作20Hz完整观测；动态场景再按风险验证是否需提频 |
| 候选mask与投影发布 | p95 ≤500 ms | 源帧提交至界面可读取，不是浏览器刷新间隔 |
| OCR采样与绑定 | 1 Hz；完成率≥95%；p95≤2 s | 包含排队；未选中未绑定、替换、超时单列，不缩小分母 |
| VLM TEXT | 事件触发＋异步更新 | 先测实际服务时间/来源年龄；不能把每2秒采样写成0.5 Hz完成 |
| PREFILL / Flow / 控制 | 1 / 5 / 30 Hz设计目标 | 真前向、合法候选和实际命令分别计数；未训练头不算能力通过 |

这些是待验收目标，不是当前均已达标。原建图实验有语义延迟/身份质量未通过项。类别/实例准入后正式入图频率另报，不将5 Hz候选发布等同5 Hz正式语义登记。

每次请求记录 `source / submit / start / ready / commit / browser-render` 时间，以及图像编码、prefill、decode、Decoder、压缩器、Flow、候选检查、控制耗时，报告p50/p95、token数、GPU峰值、队列长度和丢帧。嵌套阶段不能重复相加；跨主机时间须校准。启动/预热与运动期间统计分离。

### 4.3 优化顺序：先量测，再压缩

| 优先级 | 动作 | 正确性保护 / 输出 |
|---|---|---|
| O0 | 固定版本、模型常驻、预热、分阶段计时、只读回放基准 | 同一批输入比较；记录图像token和生成token，避免把prompt长度当全部延迟 |
| O1 | 教师/学生SYSTEM分开；共用短学生模板；五点改两点；取消二次问答 | 真实decode token/时延对照；不能按5→2推算总耗时降低60%；不删未完成Route换速度 |
| O2 | 前缀/视觉特征缓存、词表特征缓存、SDPA/FlashAttention、异步写盘 | 只复用确实不变的输入；动态地图、位置和历史顺序变化需失效；不盲复用跨请求KV |
| O3 | 固定类别YOLOE-v8s TensorRT FP16；OCR CPU线程；候选与文字解耦 | 引擎类别/hash与词表一致；无静默回退；量测GPU争用与绑定错误 |
| O4 | 按收益评估模型量化、推理引擎、解码优化 | 坐标、数字编号、Route保持、Decoder/KV接口回归；不只比较tokens/s |
| O5 | 后续MapEncoder、历史token压缩及端侧移植 | 新训练/缓存版本、端到端收益；与MapView基线分开，不阻塞当前Stage1a |

LoRA r=8主要降低训练可更新参数，不自动大幅减少部署decode耗时。部署可评估合并adapter，但必须保存原adapter/基础权重hash并做合并前后输出对照。不同backend对实际 `<REFLINE>` hidden state和K/V可访问性需验证，不接受只支持文本输出却声称完整快照可用。

#### 4.3.1 DriveVLM的可借鉴优化及本项目落点

依据[DriveVLM正式论文](https://proceedings.mlr.press/v270/tian25c.html)及其[附录D部署说明](https://raw.githubusercontent.com/mlresearch/v270/main/assets/tian25c/tian25c.pdf)。以下均为待实施/待测方案，不是本项目已取得的加速结果。

| 论文中的方法 | 本项目建议 | 依赖与验收 |
|---|---|---|
| 慢VLM与快规划系统异步执行 | VLM更新语义与名义路线；FMAE读取最新感知，控制器连续执行短前缀 | 优先落实；分别测语义来源年龄、动作发布与实际控制周期，不能用快系统频率代表VLM频率 |
| LDPNetv2压缩视觉token，裁去非信息区域 | 先缓存不变图像特征，再评估学习型历史/地图token压缩；保留标牌、路口和可通行边界 | 新压缩器需要训练；裁剪必须更新坐标映射，不能直接套用汽车图像裁剪规则 |
| 历史视觉feature memory bank与SE加权融合 | 缓存逐图像视觉特征，以源时间、相对位姿和有效性处理历史 | 编码器、预处理和图像hash变化则失效；视觉特征缓存不等于可任意复用LLM历史KV |
| EAGLE推测解码 | 先剖析TEXT的decode占比，再评估草稿模型和验证成本 | 需要适配/训练草稿模型；核验最终接受token对应的真实REFLINE状态和K/V；PREFILL模式没有长文本decode可加速 |
| 自定义Orin推理框架 | 后续单独做端侧后端与精度回归 | 先验证hidden state/KV导出，再评估INT8/INT4等通用优化；不把这些通用选项全部归因于DriveVLM |

论文报告LDPNetv2减少75%图像token、EAGLE约2.7倍decode加速，以及慢系统约400ms、快系统约130ms。它们属于论文的模型、硬件与输入配置；不能据此预计本项目同比加速，也不能将异步快系统130ms理解为语义指导仅陈旧130ms。

实施顺序固定为：**分阶段计时和异步发布 → 编码特征缓存 → 后端/精度回归 → 学习型token压缩 → 有收益时再做推测解码**。无需训练的工程项先做；压缩器或草稿模型归入后续训练计划。每项以完整请求的p95延迟、地图/编号理解、Route保持、参考线与动作输出为验收依据，不能只看tokens/s。

#### 4.3.2 本版部署实施包与消融

| 顺序 | 实施内容 | 验收与回退 |
|---|---|---|
| E0 基线 | 固定前视短模板、两点输出、模型版本及同一完整episode回放；记录视觉编码/prefill/decode/头/控制时间 | 保存原始输出与完整时延分布；旧五点只作显式历史对照 |
| E1 异步快慢链 | 语义路线异步发布、按源位姿对齐裁剪；AE最新多方向观测；轨迹短前缀接管 | 记录语义年龄、轨迹衔接与实际命令，车辆不能为等待常规VLM更新而周期性停顿；失效时仍停车 |
| E2 工程复用 | 模型常驻、视觉/词表缓存、LoRA合并对照、异步I/O、预热、融合批处理 | 仅缓存确实相同的编码；有效mask和源时间不因缓存刷新重置；不盲复用跨请求KV |
| E3 后端精度 | FP16/BF16基线，再按收益试INT8/INT4和可用attention/推理后端 | 同时回归编号、两点、Route、Decoder和K/V；质量/接口失败则保留原精度，不静默回退 |
| E4 学习型压缩 | 历史/地图/多视图token池化或学习压缩，按模块单独训练 | 当前前视细节和小标牌不能先被压掉；新权重、缓存与训练版本；比较完整任务质量 |
| E5 推测解码 | decode占主导且输出足够长时评估EAGLE类方法 | 计入草稿计算/显存，核验最终接受序列对应REFLINE状态；收益不足则不引入 |

前视VLM与多方向AE可共享满足条件的图像编码结果，但不能假定不同编码器、裁剪、分辨率的特征可互换。增加视图主要增加视觉计算/融合和传输成本，不直接增加VLM文本decode token。量化和压缩后仍需重新验证源时间、轨迹有效长度与停车条件；异步调度减少等待，不消除推理时延。

### 4.4 持续运动、更新与安全

<!-- diagram:deployment -->

图 8：慢推理完成时发布新快照，AE与控制持续运行。语义年龄从源观测开始累计，不因缓存读取或控制刷新而归零。

曲线跟踪和VLM异步执行。每条模型队列一个处理中任务＋一个最新等待任务，记录被替换请求；新有效结果按当前odom对齐并尽快接管，不等旧waypoint全部走完。前缀衔接检查位置、朝向、速度连续性；过期/错源/取消/新障碍触发独立停车，不以平滑视频替代命令日志。

参考线按源位姿变换并裁剪，`z_sem`不做刚体旋转。当前像素demo的5秒有效期、旧TEXT10秒/PREFILL3秒是不同实验配置，应各自冻结，不混写成统一部署安全阈值。阈值取决于速度、可见路线剩余长度和动态风险，必须在实测中验证。

大角度转弯可采用“停平移→原地转向→获得新可见通道→恢复平移”；这需要1.5节接口与扫掠检查。多方向AE已列为目标结构，真实覆盖、深度/激光融合与历史地图过期策略仍须实现验证；仅前向RGB的盲区不能通过训练承诺消失。

### 4.5 最终演示与验收矩阵

| 演示/评测 | 输入任务 | 必须保存的证据 |
|---|---|---|
| R2R完整任务 | 自然语言初始化Previous Route | 每个关键时刻输入/输出、示范GT、真实预测、逐字段审核、官方协议成绩 |
| 仓库环绕建图 | 完整环绕序列及最终STOP | 真实请求、递归Route、mask/OCR、语义地图、实际命令和车辆轨迹 |
| 地图辅助目标导航 | 仅目标编号，例如 `Go to sign 04/5R and STOP beside it.` | 初始RGB目标不可见、历史地图证据、Local/Route推导、真实目标邻域停车 |
| 原地旋转 | 左/右旋转再继续 | 源朝向、锁定目标yaw、实际yaw/平移量、输出更新和盲区处理 |
| 动态任务（后续） | 同一路线的横穿/绕行/恢复 | 名义路线不被动作GT污染、动态预测来源、Flow候选与独立核验 |

### 4.7 可选地图编码与端侧扩展

保留 v0.6 备选而不增加当前必选模块。触发条件为 MapView 空间/实例/连通性在独立测试持续不足，或图像输入代价超过预算。先比较渲染图、任务相关裁剪/检索、结构化节点投影，再考虑可学习压缩。

完整地图保存在外部。按 instruction、可见地标和位置候选检索当前区域、目标及连接分支；只读已知地图，不能用 Oracle 路线筛选捷径。定位不确定时保留多个子图假设；精确货架编号维持显式绑定，数据库 ID 不当作语义 token。

Graph Encoder 编码类别、文字语义、相对位置、朝向可观测性、更新时间和通道/封闭/unknown 关系；BEV 编码器处理占用/自由/未知/几何边界。Resampler 或节点投影产生有限地图 token，与图像/任务输入 VLM。32/64/128 为消融候选，不承诺无损压缩任意地图。

新投影需可核验问答/对应/参考线监督；冻结主干时保留到输入模块的梯度。与现有 MapView 控制可用证据、split、输出长度和更新预算；同时报告检索/编码成本、关键目标与分支丢失、空间关系、路线质量及端到端时延。若改为几何搜索给候选、VLM 选择，应独立标记规划分工变化。

```bash
# 人工采集：一个静态任务，浏览器遥操作
bash DynaNav/warehouse_loop/run_annotation.sh \
  --mode capture \
  --instruction 'Go straight along the aisle, turn left at its end, then continue straight toward the fire extinguisher you see.' \
  --output /data/ticvla/datasets/manual-static-new

# 重开既有人工作业，不控制车辆
bash DynaNav/warehouse_loop/run_annotation.sh \
  --mode replay --output /data/ticvla/datasets/manual-static-004

# 自然语言静止参考线诊断，不用几何路径替代模型结果
bash DynaNav/warehouse_loop/run_navigation.sh \
  --instruction 'Move backward five metres.' \
  --execution-backend reference-only \
  --output /data/ticvla/outputs/navigation/reference-new --keep-viewer
```
