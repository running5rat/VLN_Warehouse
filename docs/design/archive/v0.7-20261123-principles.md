# 动态仓库 VLN：系统原理与算法方案 v0.7

2026-11-23 · 算法方案修订

## 阅读说明

本方案研究如何将自然语言、视觉语义地图与动态运动规划结合，使仓库机器人完成地标导航、探索和跟随。全文按照模型、训练、数据与部署四个部分展开，聚焦模块分工、信息表示、学习目标和实验方法。

核心选择是：**VLM 与 Reference Decoder 使用前视语义证据；Action Expert 使用多方向当前感知；两个图像锚点表达局部意图，连续参考线表达路线形状，动作轨迹表达动态可执行运动。**

图中的仓库 RGB、检测结果和地图来自已有示教演示。多方向感知、两点输出及动作候选的组合展示属于目标架构示意，不作为该演示已完成全部模型训练的证明。本文不包含代码索引、数据存储设计和运行验收清单；相应细节保留在工程文档中。

## 1. Model Pipeline

### 1.1 总体架构：语义路线与动态动作分工

<!-- diagram:overview -->

图 1：仓库数据驱动的模型总览。顶部为同一演示时刻的真实 RGB、检测与历史地图局部；语义文字取自 Codex 代标，展示其在目标 VLM 架构中的位置。多方向视场、两点与候选轨迹为算法示意。

系统包含两个不同时间尺度的决策层。语义层理解任务、判断地标关系并形成名义路线；动作层结合最新障碍观测，将路线变为可执行的时间轨迹。地图支持跨视野和跨时刻的空间推理，控制器跟踪所选轨迹的短前缀。

| 模块 | 主要输入 | 主要输出与职责 |
|---|---|---|
| 语义建图 | RGB-D、局部 odom、实例分割、文字识别 | 具有物体位置、类别和可读属性的空间记忆 |
| VLM | 前视图像、检测叠图、历史语义地图、剩余 Route、历史 Local 和相对运动 | Landmark、Local、更新 Route、两个图像锚点 |
| Reference Decoder | 实际处理 REFLINE 查询后的隐藏状态 | 车体系连续名义路线及有效长度 |
| Context Compressor | 同次推理的 K/V 上下文 | 紧凑语义条件 z_sem |
| FlowMatchingActionExpert | 多方向当前感知、参考线、z_sem、机器人状态 | 九模态短时动作轨迹 |
| Scorer 与控制器 | 候选轨迹、环境、机器人动力学 | 可行候选排序与速度、角速度控制 |

#### 1.1.1 为什么前视语义与多方向动作分开

前视图像适合解释“沿通道前进、到标牌旁停止”等任务，也便于沿用前视导航数据。历史地图补充已经观察但当前看不见的地标。VLM 不必在每次推理中处理所有方向的高清图像，因而可以控制视觉 token 和推理延迟。

动作层必须关注转向时的侧方扫掠区域、侧后方接近物体和动态障碍。因此，AE 使用前、左、右、后方向的当前观测，并通过相机外参、时间信息和视图有效性融合。相机数量不等于完整覆盖；实际可观测范围还由视场角、遮挡和安装位置决定。深度用于度量空间，局部 odom 用于关联不同时刻的观测，二者不由自然语言定位取代。

### 1.2 VLM 的输入与递归推理

首轮以完整用户指令初始化 Previous Route；后续以模型上轮保留的剩余任务作为输入。Previous Local 与相对运动帮助模型在短期图像退化时延续定位关系。原始任务作为评价依据保留，但在当前 route-only 方案中不重复写入每轮提示。

```text
Previous Route: <remaining task, initially the full instruction>
Previous Local: <latest supported landmark-relative description, or unknown>
Motion since previous Local (<age> s): x_m=<x>, y_m=<y>, yaw_rad=<yaw>
Current detectable categories: <categories supported by current detections>
Completion evidence: <confirmed or unverified>

<image>Historical forward RGB, 3 seconds ago, if available</image>
<image>Historical forward RGB, 2 seconds ago, if available</image>
<image>Historical forward RGB, 1 second ago, if available</image>
<image>Current forward RGB</image>
<image>Current detection overlay</image>
<image>Previously observed semantic map, aligned to the current body frame</image>
```

相对运动表示“当前车体在上一 Local 对应车体系中的位姿”：x 向前、y 向左，位移单位米，yaw 为逆时针弧度。地图只包含此前已经观察到的信息，不能使用任务结束后的完整地图。检测叠图帮助将语言类别与可见物体对应；像素 mask 用于几何投影，不要求在提示中罗列实例元数据。

递归变量是 Local、Route 和逐步扩展的地图。Route 保留未完成步骤及其顺序；Local 根据当前图像、历史关系和运动更新。错误的历史文本可能传播，因此模型应优先采用新的可靠观测，并区分当前观察与历史推断。该闭环必须用完整任务评价，单帧答案合理并不保证后续任务保持正确。

### 1.3 结构化输出与语义职责

学生模型采用简短固定格式，避免输出大量可由外部关联的信息：

```text
<landmark>[categories]</landmark>
<local>landmark-relative position and heading, or unknown</local>
<Route>remaining navigation commands, or DONE</Route>
<waypoint>(u1,v1);(u2,v2)</waypoint>
<REFLINE>
```

| 输出 | 含义 | 表达要求 |
|---|---|---|
| Landmark | 值得登记的可见物体类别 | 最多三类，来自当前检测；无支持时为 [] |
| Local | 相对地标的位置与朝向 | 英文，不超过 90 字符；依据不足时 unknown，历史推断明确标注 |
| Route | 尚未执行的导航命令 | 不超过 600 字符；保留后续转弯、目标和最终停等，不重复描述当前场景 |
| Waypoint | 当前前视图像上的两个有序空间锚点 | 原图像素坐标，近点在前、远点在后；无法表达时为 [] |
| REFLINE | 提取路线特征的查询标记 | 对应隐藏状态输入 Reference Decoder，不生成密集坐标文本 |

编号应服务于 Local 的地标关系表达，而不是成为新的物体类别。未进入当前视野的指定目标可以保留为 Route 的寻找目标，但不得凭空编造其位置。只有整个任务完成且存在完成依据时，Route 才能输出 DONE；空锚点本身不代表任务完成。

稳定跟随阶段可使用 PREFILL_FOLLOW：保留视觉与目标条件，仅处理查询标记，不生成完整文本。任务变化、目标丢失或语义指导失效时，再进行 TEXT 推理。

### 1.4 两个图像锚点与连续参考线

<!-- diagram:anchors -->

图 2：同一仓库 RGB 上的两个锚点与车体系连续路线。锚点和曲线为说明表示关系而绘制，不是该帧模型预测或度量真值。两点提供语义对齐，连续形状由 Decoder 学习。

#### 1.4.1 两种表示的互补作用

Waypoint 是便于语言监督、可视审核的稀疏路线表达；ReferenceLine 是动作模型需要的连续几何条件。只保留两个点会丢失弯道形状、有效长度和局部切向；只保留隐式参考线则难以直接检查视觉语言意图。因此保留两者，但将文本锚点由五个减少为两个。

两个锚点取自同一条批准路线的**当前可见且有可靠投影的前缀**：近点取该前缀约半弧长位置，远点取其末端。图像坐标不超过 RGB 边界，路线目标是可通行位置，而不是货架或标牌表面。无法形成可靠前缀时，不强制凑齐两个坐标。

#### 1.4.2 图像与车体系的几何联系

以针孔相机和光轴深度 z 为例，像素 p=(u,v) 的相机点为 z·K⁻¹[u,v,1]ᵀ，经相机到车体变换得到度量位置。不同深度定义需使用对应的投影模型。地图中的路线也可通过相反变换投影回 RGB，用于检查路线是否与可见通道一致。

Reference Decoder 直接学习密集路线，不以两点插值作为替代。训练时锚点与参考线来自同一条路线；推理时检查两者的方向、顺序及几何一致性。静态路线表达任务意图，动态局部避让由 AE 完成，不要求每次绕障都改写高层参考线。

### 1.5 语义地图：视觉对象与空间记忆

#### 1.5.1 几何与语义的联合表示

深度反投影得到三维表面，利用局部 odom 累积为已观测几何。实例分割为表面赋予对象边界，VLM 选择其中具有导航价值的类别；学习型 OCR 为相应物体补充文字属性。跨帧几何关联将重复观察聚合成物体级记忆，供后续视野外目标推理使用。

所有有效障碍深度都参与几何建图，语义选择只影响物体记忆，不能让未被 VLM 选中的障碍消失。普通重复货架和可区分编号承担不同作用：前者提供通道结构，后者可用于区分具体位置。文字与几何关联的联合证据比单次文字识别更可靠。

#### 1.5.2 面向 VLM 的地图表达

首版采用渲染后的语义 BEV 作为视觉输入，将已观测空间、物体位置与可读属性放在同一张图中。它与当前 RGB 互补：RGB 支持当前可见物体判断，地图支持已观察但当前不可见的地标关系。未观察区域与已确认自由空间应有清楚的视觉区别。

后续可研究学习型 MapEncoder，以物体、局部几何和空间关系生成有界地图 token。先固定渲染接口建立基线，再单独比较学习型表示，避免同时改变地图表示、感知和导航模型而难以解释收益。

### 1.6 Reference Decoder 与语义上下文

#### 1.6.1 从查询特征到连续路线

REFLINE 对应的隐藏状态驱动路线解码器。首版使用隐藏维度 256，预测 8 个控制点，通过三次 B-spline 得到 32 个有序二维点及有效长度。路线位于源时刻车体系中，表示空间几何而非轮速或固定到达时间。

参考线更新时，以局部 odom 对齐到当前车体系并裁去已经执行的部分。几何关系为：

```text
p_current = inverse(T_odom_current) · T_odom_source · p_source
```

该变换保证机器人在语言推理期间继续运动时，仍能使用旧路线的剩余段。参考线损失同时监督位置和有效性，不能将未标注路线误当作停止路线。

#### 1.6.2 从 K/V 到紧凑语义条件

同次推理的 K/V 经过归一化和投影，再由 16 个学习查询进行交叉注意力，得到 z_sem∈R^(16×512)。该条件携带目标、任务和场景关系；AE 同时读取语义年龄与相对运动，判断其与最新观测之间的变化。

z_sem 是语义表示，不做刚体旋转；参考线是几何表示，需要坐标对齐。两者共同桥接低频语言理解和高频动作预测。压缩后的固定 token 数还限制动作侧交叉注意力的开销。

### 1.7 多方向 FlowMatchingActionExpert

#### 1.7.1 条件融合与九模态表示

多方向图像经视觉编码，并加入方向、外参及时间信息；动作层将其与局部几何、当前速度、对齐参考线、z_sem 及上一轨迹剩余段融合。缺失视图采用有效性掩码，不能用前视复制成多方向观测。

九模态为横向 LEFT／CENTER／RIGHT 与纵向 STOP-YIELD／FOLLOW／PROCEED 的组合。横向相对于名义参考线或绕障通路定义；FOLLOW 表示沿路线跟进和调速，不等于高层的行人跟随任务。该分解为绕行、停等和前进提供不同动作假设，而不是建立九套独立模型。

#### 1.7.2 条件 Flow Matching

设动作 GT 为 x₁，高斯噪声为 x₀，生成时间 τ∈[0,1]。使用线性路径 xτ=(1−τ)x₀+τx₁，网络预测速度场 vθ(xτ,τ,c,m)，训练目标为 x₁−x₀。条件 c 编码一次后共享给各模态 m。

```text
L_FM = E[ ||v_theta(x_tau, tau, c, m) - (x1 - x0)||² ]
x_(tau+Δtau) = x_tau + Δtau · v_theta(x_tau, tau, c, m)
```

首版主干采用 512 隐藏维度、3 个共享 Transformer block、8 个注意力头；以 4 步 Euler 采样。输出为每模态一条 30 点 XY 时间轨迹，物理时间间隔 0.1 秒，即 3 秒视窗。生成时间 τ 与轨迹的物理时间是两个不同概念。

参考线提供静态任务方向，多方向当前感知决定如何避让动态物体；二者分工减少语义模型学习瞬时控制细节的负担。多模态训练需要同场景多策略示范或有效模态覆盖，单条示范不能同时监督其他八种行为。

### 1.8 轨迹选择、控制与原地转向

候选首先通过碰撞和动力学约束，再按进展、参考线偏离、舒适性及安全距离排序。规则评分作为初始基线，后续学习型 Scorer 以独立规则评价和候选排序为监督。控制器跟踪选定轨迹的短前缀，新候选到来后重新规划。

原地转向是必要的动作能力：急转弯、狭窄区域重新定向及主动观察都可能需要它。两个 RGB 点和纯 XY 轨迹不能完整表达位置不变而朝向变化，因此需要独立的朝向／角速度动作表示。空 Waypoint 既可能表示暂无可靠路线，也可能对应旋转，不能自动解释为 STOP。

大转角时可将旋转与前进分段执行，减少未观察侧方被连续扫掠的风险，但原地旋转也需检查机器人 footprint。多方向感知降低盲区风险，不能替代轨迹可行性检查。物理倒车涉及后向观测与有符号速度，独立于当前仅做参考线表达的倒退诊断。

## 2. Training Schedule

### 2.1 训练路线与参数更新

首选 **InternVL3-1B＋语言 LoRA＋完整训练 Reference Decoder**。基础视觉编码器冻结，先建立文本与路线学习的稳定基线，再比较 LoRA 秩、模型容量，最后在数据质量和规模稳定后尝试语言侧全量 SFT。LoRA 本身也是 SFT 的一种参数更新方式。

| 阶段 | 学习目标 | 参数更新 |
|---|---|---|
| Stage1a 标准导航 | 地标、位置关系、递归剩余任务与静态参考线 | 语言 LoRA、完整 Reference Decoder |
| Stage1b 仓库迁移 | 编号定位、地图依赖任务与仓库指令 | 延续语义与参考线训练，保留通用导航数据 |
| Stage2 动态动作 | 多方向动态避障与平滑可执行轨迹 | 冻结 VLM／Decoder，训练 AE、动作融合和上下文压缩器 |
| Stage3 候选评分 | 具体候选的质量与排序 | 训练 Scorer，保留规则评分对照 |
| Stage4 闭环改进 | 偏航恢复、纠正与困难交互 | 先 DAgger，再按需进行动作侧 RL |

### 2.2 LoRA、容量与全量 SFT 对照

#### 2.2.1 LoRA 秩

以语言所有层 Q/K/V/O 的 r=16 为基线，对照 r=8、16、32。固定目标模块、缩放比例、样本曝光量和评测条件；Q/V-only 作为独立的低成本实验，不与秩变化混在一起。Reference Decoder 始终全参数训练，不因 LoRA 秩变小而缩减路线学习。

秩影响可学习增量的容量，不决定唯一的最佳数据量。若训练和验证均差，应先区分容量不足、优化问题与标签错误；若训练好而验证差，优先增加布局覆盖和降低重复偏差，而非直接增大秩。

#### 2.2.2 模型容量与全量更新

先在同系列 InternVL3-1B 与 2B 上比较语义保持、路线质量、闭环表现和端到端时延。4B 级模型若更换语言骨干或预训练数据，作为模型选择对照，不将差异全部归因为参数量。

全量 SFT 在数据审核稳定、规模试验显示收益、LoRA 仍存在容量瓶颈且资源允许时开展。首轮全量更新语言侧，视觉编码器保持冻结；与 LoRA 使用匹配的数据与训练预算。大模型或全量训练不是低质量递归标签的替代品。

### 2.3 首轮数据组成与采样

以下比例是按**有效训练样本采样次数**计算的起始实验配置，不是经过验证的最优配方。先按来源和任务采样，再在任务内按关键事件采样，避免长直行片段占据大部分梯度。

| 阶段 | 起始配比 | 目的 |
|---|---|---|
| Stage1a 初始 | 100% 合格 R2R | 单独验证导航监督与中间语义监督的收益 |
| Stage1a 扩展 | R2R 72%、英语 RxR 18%、针对性 VQA 10% | 扩展语言与路线多样性，补充空间关系理解 |
| Stage1b | 仓库 50%、R2R/RxR 40%、针对性 VQA 10% | 仓库适应与通用导航能力保持 |
| Stage2 | 动态仿真机器人 60%、真实机器人 30%、可适配人类轨迹最多 10% | 覆盖动态交互并保持机器人可执行性 |
| Stage3 | 按候选风险、失败类型及模态覆盖分层 | 学习候选质量，避免只见容易区分的负例 |

仓库池内部先安排约 20% 的纠正／恢复样本，即整体样本约 10%。VQA 聚焦地标指代、相对方向、地图与 RGB 对应、历史与当前区分，以及剩余步骤保持；不要求每条 VQA 都具有路线监督。人类动作数据若无法验证米制尺度和机器人可执行性，关闭该池，其份额按 2:1 分回仿真与真实机器人池。

可借鉴 LightNav-0 分阶段改变视觉理解与导航动作比例，以及 ABot-N0 在动作学习中保留语义回放的思路。本方案 Stage2 冻结 VLM，因而普通 VQA 文本损失不能改善被冻结的语义网络，不直接照搬其他模型的混合比例。辅助 VQA 建议进行 0／10／20% 对照。

### 2.4 监督目标与规模试验

#### 2.4.1 文本与参考线联合监督

语义阶段以有效答案 token 的交叉熵为主，结合参考线点位置、有效长度及有效性监督。两点锚点从批准路线投影得到，与连续线共享几何来源；投影可靠时可加入锚点一致性辅助项。

```text
L_semantic = L_text + λ_ref L_reference + λ_valid L_validity
             + λ_anchor L_anchor_consistency
```

未标注字段关闭相应损失；没有动作标签的静态样本不产生停车动作 GT。teacher-forced 损失用于拟合诊断，自由生成与完整任务递归用于评价实际推理，两者分别报告。

#### 2.4.2 数据规模与消融

按审核后的约 300、1,000、2,000–3,000 个任务逐步比较收益。任务数与独立建筑数不是同一概念，扩量应增加布局、路径、转向和地图依赖的覆盖。各规模从同一原始初始化独立训练，不将连续续训效果当作纯数据规模效应。

核心消融包括：仅轨迹监督与增加 Landmark／Local／Route；无历史 Local 与带相对运动的历史 Local；无语义地图与语义地图；不同 LoRA 秩；不同模型容量。先进行低成本单因素试验，不做全部因素的笛卡尔积。

### 2.5 动作、Scorer 与闭环学习

动态动作阶段冻结语义模型和 Reference Decoder，使用相同任务路线与不同动态交互下的动作 GT。压缩器和动作侧投影与 AE 联合训练；语义特征来自冻结学生模型，而不是教师模型替代特征。训练加入语义延迟和位姿变化，让 AE 学会使用较旧语义与最新感知。

Scorer 读取实际候选及环境，以碰撞、动力学、进展、偏离、舒适性等分项监督和排序监督训练。求解器失败不能直接证明整个模态不可行；未验证行为不作为确定负例。

DAgger 优先收集偏航、错转、目标丢失和重新定位等模型实际访问状态，以专家纠正补充离线分布。可选 RL 放在模仿学习稳定之后，用于动作侧交互改进；语义更新与动作更新分开研究，避免两者同时变化导致难以归因。

### 2.6 评价标准

| 层面 | 关注指标 | 要回答的问题 |
|---|---|---|
| 语义 | 地标依据、Local 关系、剩余步骤保留、错误 DONE | 模型是否理解场景和任务进度？ |
| 参考线 | 方向、位置误差、有效长度、可见性、锚点一致性 | 语义意图是否变成正确空间路线？ |
| 动作 | 碰撞、动力学可行率、进展、平滑性、恢复 | 是否能应对动态场景并执行？ |
| 标准导航 | 对应 benchmark 的 SR、SPL、NE 等 | 相同评测协议下能否改善导航结果？ |
| 部署 | 完成频率、p50/p95 延迟、显存和能耗 | 收益是否可在目标硬件保留？ |

数据按建筑或布局族划分，同路线多指令和外观变体留在同一划分中。RGB-D＋理想 odom 的扩展设定与标准 benchmark 设定明确区分。最终重要对照报告多随机种子的均值与波动，不用训练 loss 下降替代导航结论。

## 3. Data Engine

### 3.1 数据来源与任务构成

数据引擎将完整任务的观测、语言进度与几何监督对应起来。静态名义路线训练 VLM／Reference，动态行为轨迹训练 AE，候选评价训练 Scorer；三者共享任务背景，但不混用监督目标。

| 来源 | 主要价值 | 使用条件 |
|---|---|---|
| R2R / 英语 RxR | 标准指令导航、路线顺序、语言多样性 | 回放获得同步 RGB-D、标定和理想局部 odom；官方划分保持独立 |
| 仓库人工示教 | 精确任务语义、编号定位、完整任务基准 | 人工审核关键时刻及对应未来路线 |
| 重建／仿真场景多任务 | 控制路径、目标和环境组合 | 新任务具备匹配且可执行的轨迹来源 |
| 机器人运动数据 | 实际动作和动态交互 | 尺度、时间、传感器及动力学可核验 |
| 人类视频与空间 VQA | 语义、指代、关系与部分运动补充 | 只使用可信字段，不能直接等同机器人动作 |

### 3.2 观测与监督的因果边界

每个训练时刻包括部署可获得的图像、已观测地图、局部运动和历史文本，以及独立的监督标签。未来示范轨迹可以用于构造参考线 GT，但不能进入语义教师或学生观测；最终完整地图也不能替代当时的历史地图。

| 数据部分 | 内容 | 用途 |
|---|---|---|
| observation | 当前／历史图像、当时地图、历史 Route／Local、相对运动 | 学生与教师的因果输入 |
| supervision | 批准文本、路线、锚点；后续动作与评分 | 对应损失的监督 |
| provenance | 场景、任务、示范及标注来源 | 划分、追溯与质量分析 |

关键时刻应覆盖转向前后、目标出现、重定位和停止，并保证下一次推理发生在上一参考线有效范围耗尽前。纯旋转保留朝向变化，不能因 XY 位移小就误标为停止。

### 3.3 静态语义与路线标注

#### 3.3.1 人工基准

人工驾驶一个完整任务，再离线回放标注关键时刻。参考线从后续静态示范轨迹提取、去除停顿重复点并转到当前车体系；人工修正明显抖动和不合理切角。两个锚点由同一条批准路线的可见前缀派生，避免文本与几何各画一条路线。

人工填写 Landmark、Local 和剩余 Route；后一时刻依据前一时刻的剩余任务标注。未来轨迹只是标注辅助，不应使早期文本提前知道尚未看到的地标或目标状态。

#### 3.3.2 语义教师

教师只补充语义中间标签，不生成度量路线。统一输出为：

```json
{
  "landmark": ["sign"],
  "local": "By sign 03/4R, facing toward the aisle end.",
  "route": "Continue to the aisle end, turn right, follow the next aisle and stop."
}
```

该例只说明格式。实际教师读取当时 RGB、检测和历史地图，英文 Local 不超过 90 字符、Route 不超过 600 字符；字段含义与学生一致。教师可以使用更详细的审核规则，学生用短 SYSTEM 和监督学习掌握输出习惯，不必逐字复制教师的长提示。

首轮使用选定的 Qwen Plus 标注配置保持可比性；比较不同教师时使用相同输入和几何标签。waypoint 与 ref_line 均由示范轨迹产生，不提供给语义教师作为提示。

#### 3.3.3 闭环标注与质量审核

模型标注采用自身上一轮有效 Route／Local 和已经生成的语义地图递归输入，以暴露任务截断、错误记忆及地图污染。人工修订标签与原始闭环输出分开评价，不能通过事后修订历史让模型表现看似正确。

审核覆盖整个任务：Landmark 是否可见并有检测支持，Local 是否表达有依据的位置朝向，Route 是否遗漏后续步骤或虚构方向，DONE 是否有完整任务完成依据。错误输入影响后续时刻时，评价其传播范围，而不只统计单帧 JSON 合法率。

### 3.4 重建场景中的多任务生成

#### 3.4.1 何时需要轨迹 Oracle

场景重建提供可观察的环境，但不会自动提供每条指令的正确行动。若只是重写同一条路径的语言或提取合法子任务，可以复用已核验示范；改变起点、目标、途经条件或路线顺序后，需要新的人工示范或轨迹 Oracle。

静态最小 Oracle 可以由 NavMesh／占用地图搜索、机器人 footprint 与转向约束、控制器执行核验组成。它依据任务的有序条件求路，而不是只求起终点最短路；“第二路口右转”等要求必须在路线中得到满足。静态阶段不必先引入动态 AL-iLQR。

#### 3.4.2 批量生成策略

先验证场景尺度、可行走区域和目标实体，再采样起终点与有序途经约束；生成可执行路线后，产生与路线匹配的自然语言任务。对固定用户指令则反过来核验其语义约束是否可执行。轨迹提供几何 GT，语义教师提供当时可推断的文本，两者经过一致性审核后组合。

同一场景可改变目标、路径、地标表达和初始视角，但大量同布局任务不能代替未见布局。可借鉴 ABot-N0 的任务扩展与自动核验思路，并增加错转、越过路口、相似编号、遮挡和局部感知退化后的恢复样本。

### 3.5 动态动作与候选评分数据

在静态任务和名义路线不变的基础上，增加横穿、局部阻挡、让行及阻挡解除等动态条件。Lattice 提供不同绕行／纵向策略初值，AL-iLQR 或人工示范形成动作候选，再由独立 ScorerOracle 核验约束与质量。局部避让不覆盖静态路线 GT；永久封路引起的任务级重规划另作监督。

动态 Oracle 依据当前与历史观测预测障碍运动；未来真值只用于独立评价。开源人类或机器人数据缺乏深度、尺度、名义路线时，不生成未经支持的碰撞分数或九模态完整标签。一条示范只监督其可判定的模态，其他模态保持未知。

### 3.6 数据质量与扩量原则

首先控制标签错误，再增加数量。重点风险包括递归任务截断、错误完成、文字与对象错绑、路线与语言不一致、未来信息泄漏以及同路线跨训练／测试划分。模板一致性、模型间一致性可用于筛查，但不能替代独立证据与人工抽检。

扩量优先补充稀缺情形：转弯、地图依赖、视野外目标、停止、恢复和动态交互。重复直行帧只能增加曝光量，不能增加等价的任务多样性。评价按完整任务、关键事件和布局分别统计，防止容易样本掩盖关键失败。

## 4. Deployment Optimization

### 4.1 异步语义与连续控制

<!-- diagram:deployment -->

图 3：语义推理与快速动作控制在不同频率下运行。新语义结果到来时按实际运动对齐后接管，车辆不必等待旧参考线走完；图中条带仅表示调度关系，不表示实测耗时。

VLM 负责低频任务推理，AE 与控制器持续使用最新可用语义和当前感知。推理期间机器人仍可沿有效路线运动；新参考线发布后对齐到当前车体并平滑接续。动作层始终根据当前障碍检查旧计划，异步不能意味着无条件沿旧路线前进。

以语义年龄、相对位姿和剩余参考线长度作为条件，让模型显式处理延迟。近期观测变化较大、路线覆盖不足或跟随目标丢失时触发语义刷新；有效证据不足时减速或等待。

### 4.2 分层性能目标

| 层级 | 目标节奏 | 优化重点 |
|---|---|---|
| RGB-D 与几何感知 | 约 5 Hz | 同步、传输、分割与局部几何计算 |
| AE 与轨迹选择 | 约 5 Hz | 多视图条件编码复用、小步数采样 |
| 控制 | 约 30 Hz | 新轨迹接续、跟踪与运动约束 |
| VLM TEXT | 按任务与变化触发 | 视觉 token、prefill、decode 与生成长度 |
| PREFILL_FOLLOW | 约 1 Hz 的初始目标 | 减少不必要文本解码并保持目标条件 |

这是方案目标而非已实现性能结论。初期工作站完成语义推理，机器人端保留低延迟感知和控制；后续根据通信、功耗与时延结果决定端侧迁移范围。报告从源观测到结果可用的端到端延迟，不以单一模型 tokens/s 代替系统响应。

### 4.3 推理优化路径

#### 4.3.1 输入与表征压缩

优先采用短 SYSTEM、两个锚点及有界历史，避免重复自然语言说明。固定核心检测类别时复用类别特征；历史图像特征与地图编码在证据未改变时缓存。当前多方向 AE 仍使用新观测，不因语义缓存而停用动态感知。

后续训练历史视觉 token 压缩器与学习型 MapEncoder，分别比较输入预算、语义保持和路线质量。压缩是学习与表示问题，不等价于直接删除看似重复的历史信息。

#### 4.3.2 数值与算子优化

先建立 BF16／FP16 对照，再按模块测试 INT8／INT4、融合算子、高效 attention、编译和 TensorRT 等后端。LoRA 合并可减少额外低秩分支开销，但不保证总体时延必然下降。多方向图像可以共享编码器并批处理，是否与 VLM 共享特征取决于预处理和骨干是否一致。

部署优化必须保留实际 REFLINE 查询对应的隐藏状态及所需 K/V；只返回文本的服务不足以连接本方案的 Decoder 和 AE。所有加速均同时测语义输出、路线误差与控制表现。

#### 4.3.3 借鉴 DriveVLM 的快慢协同

借鉴 DriveVLM／DriveVLM-Dual，将较慢视觉语言理解与更快的运动规划分工，并用结构化中间表示连接。这里对应前视语义与参考线、多方向动作规划的组合；不照搬自动驾驶的车道假设和传感配置。

可借鉴其视觉表示压缩及推理解码加速思路，按实际收益评估 token 压缩与 EAGLE 类推测解码。短文本、较小骨干和中间特征需求可能减少推测解码收益，因此需统计草稿模型开销、接受率和端到端延迟。被拒绝草稿的隐藏状态不能作为最终路线特征。

### 4.4 优化实验与能力保持

部署实验按异步调度、特征缓存、精度／后端、学习型压缩、解码加速的顺序逐项加入。固定任务和观测，比较 p50／p95 延迟、峰值显存、能耗及模型质量，避免多个优化同时变化而无法归因。

语义层主要观察任务保持和地标关系；几何层检查两个锚点与连续路线；动作层检查轨迹可行性、候选覆盖和连续运动。某项优化只提升速度但增加错误停止或路线偏离时，不视为等价部署。
