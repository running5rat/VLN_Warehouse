# 静态导航数据组成与格式对齐实施计划

更新：2026-10-15。状态：待实施计划；本文不代表数据已经转换或已开始训练。

## 1. 本轮决策和能力边界

本轮优先推进原七步的第5步“数据池组成”和第6步“数据审计、格式对齐”。暂缓第3、4步中的动态环境Oracle、动态轨迹标注和模态标注，不运行AL-iLQR、动态Isaac试验或Flow/Scorer训练。保留其代码与数据字段，不删除已有产物。第7步本轮只做数据加载与监督mask检查，不扩成正式训练。

当前可以称为“静态标注链路可用”，不能称为“无人值守自动标注验收完成”：

| 能力 | 实际状态 | 本轮如何使用 |
|---|---|---|
| 人工采集、回放、英文文本和参考线审核 | 已有批准的 `manual-static-004`，10个关键时刻 | 人工基准与回归，优化权重为0 |
| 未来轨迹提取参考线与同线五锚点 | 已实现；新增候选不自动批准 | 几何候选生成与格式核验 |
| 会话辅助语义提议 | 最新37＋17份格式/来源通过，未人工批准 | 候选文本和工具回归 |
| 真正API请求、响应保存、递归Route | 入口存在，真实API验收未完成；仅最多6帧试验包 | 可独立做小样本验收，不阻塞来源审计 |
| 整段API批处理、断点恢复、审核后统一导出 | 还需少量工程接线 | 需要批量标注时再补，不声称现成可运行 |
| 无行人叉车样例 | 静态相机重渲染，路径源于动态录制；相机中心位姿 | 回归/观察素材，非批准的车体路线GT |

现有 `semantic-session` 不会主动调用模型。54份提议没有API响应ID、独立调用耗时或盲测语义准确率。冻结文本仅表示固定实验版本，不表示批准标签。

若继续API自动标注，最小剩余工作是：配置真实端点并完成最多6帧试验；逐字段审核；显式支持整段包与断点续传、失败隔离、预算和幂等；将批准提议与几何修订绑定后导出。恢复时复用已保存的最后合法Route/Local，不把每6帧切片当作新任务；网络超时的请求保持不确定状态，不自动重复计费。尚未批准的样本不能通过改变manifest标志进入训练。

## 2. 按v0.6训练阶段安排数据

依据设计文档9.1、9.4–9.7节；继续使用MapView渲染接口，不同时开发MapEncoder。

| 阶段 | 所需数据 | 本轮准备范围 | 暂不覆盖 |
|---|---|---|---|
| Stage 1a，可选参考线头预热 | 审核的静态路线、有效长度、源TF和同线五锚点；可选因果地图问答 | 静态几何池、有效mask、训练输入适配 | 新地图编码器训练、未经核验几何 |
| Stage 1b，VLM＋参考线联合训练 | 英文instruction、历史RGB/MapView、旧Route/Local、执行事实、新结构化文本、参考线 | 优先准备TEXT：地标目标、路线顺序、进度更新、等待/停止、未知定位 | PREFILL_FOLLOW与跟随数据暂缺，不能宣称完整1b混合模式就绪 |
| Stage 2，Flow＋动作侧投影/压缩 | 冻结语义模型的真实特征、对齐参考线、机器人状态、有效模态和时间轨迹 | 只保留schema与来源目录 | 动态动作GT、模态生成、训练 |
| Stage 3，Scorer | 具体候选、独立评分与当前生成器版本 | 字段占位，loss关闭 | Oracle评分、负例与训练 |
| Stage 4，DAgger | 真实闭环访问状态、失败、接管及重标注 | 保留来源扩展能力 | 闭环采集与重训练 |

倒退只保留已有诊断用途，不因数据里有负向位移就产生可执行倒车监督。只有静态TEXT数据时，不将其复制为跟随PREFILL样本。

### 数据池与初版配比

本轮先输出“合格样本清单＋建议采样配方”，不实际启用训练。

| 池 | 内容 | 可承担监督 |
|---|---|---|
| 人工基准/回归池 | 已反复查看的人工episode、54份提议、旧144帧测试及派生视频 | 回归检查；不参与优化和独立测试 |
| 仓库静态主池 | 后续独立静态任务、审核的RGB-D/车体轨迹和文本 | 完整TEXT、参考线、因果MapView |
| 外部静态导航池 | 审计合格的R2R/RxR连续环境记录、NaVILA相应子集等 | 已核验的文本/路线字段；不默认有地图或车体轨迹 |
| 辅助语义池 | 静态目标指代、空间关系、已观测地图事实问答 | 对应答案token或单独字段；无几何时关闭几何loss |
| 隔离池 | 动态避让路径、相机外参未知、任务不匹配、许可/尺度未知、未批准提议 | 保存原因，训练权重0 |
| 动作/评分池 | SCAND/GND等未来审计来源及动态Oracle | 本轮禁用 |

建议首轮Stage 1b候选采样比例为仓库静态70%、外部静态导航20%、辅助语义10%；这是待数据审计验证的起始方案，不是已有数据量或最佳比例。仅在每池有合格数据时成立；缺失池列为缺口，任何重新分配须写入新版本配方，不能用回归数据补足。Stage 1a只从有批准参考线的池取样，并独立记录其来源比例。

先采来源/任务，再采episode/关键事件，避免长直行视频主导。至少分别统计起步、直行、转向前/中/后、目标出现、接近、停止、无法确定位置；这些是覆盖维度，不是人工预拆给部署VLM的任务树。初版同一episode不超过某批有效样本的10%；小规模接口夹具不满足时明确标记，不当正式配方。比例和上限最终按合格episode数量冻结，不按总RGB帧数计算。

## 3. 数据来源优先级

截至本机上次审计：DynaNav有105个原始CSV episode，其中仓库30段；SCAND/GND目录没有可用episode。它们都不是已批准训练量。第一项工作须刷新库存；已有审计只扫描 `trajectory.csv`，后续要同时识别压缩包、ROS bag/MCAP、JSONL/NPZ和图像目录，不能把“未找到CSV”普遍解释为没有数据。

| 优先级 | 来源 | 具体做法与限制 |
|---|---|---|
| P0 | 已有人工静态工程和无行人回放 | 校准schema、坐标、Route链、mask及审核导出。保留回归身份，不把相机重渲染当机器人示范 |
| P1 | 本地DynaNav/TIC-VLA | 全量盘点，原episode去重；先筛查任务、静态性和相机/车体关系，再固定最多10个转换候选。动态记录只进入隔离/辅助池，不把避让轨迹当静态名义路线 |
| P1 | NaVILA的R2R/RxR等可用子集 | 先查字段和资产可得性；同底层R2R/RxR轨迹须跨发布渠道去重。图像/文本可用不代表连续位姿、深度和机器人外参可用 |
| P2 | R2R/RxR的VLN-CE版本 | 作为外部静态连续导航首选。先核对官方split、场景访问条件和连续回放；原始图节点路径不能靠直线插值宣称可通行连续轨迹 |
| P2 | REVERIE | 优先用于目标指代、可见物体与到达语义审核。对象标注与导航路径不等于现成米制控制轨迹；不把隐藏目标框/ID输给教师 |
| 暂缓 | SCAND/GND、人类运动、动态Oracle | 仅登记实际可用文件和来源说明；不转换动态动作、不机器人化人类轨迹，不生成模态GT |

NaVILA发布说明区分标注、图像和需另行渲染的EnvDrop数据；因此逐子集审计，不整体宣布可训练。[NaVILA官方数据说明](https://github.com/AnjieCheng/NaVILA)

VLN-CE提供R2R/RxR连续环境接口；RxR也有发布的guide/follower pose traces，需保留两者区别，不能将人类视点运动视为轮式机器人动作。[VLN-CE](https://github.com/jacobkrantz/VLN-CE)、[RxR](https://github.com/google-research-datasets/RxR)

REVERIE提供指令、路径与目标物体相关标注，适合补目标指代任务；只使用对应split允许的数据。[REVERIE](https://github.com/YuankaiQi/REVERIE)

LightNav-0可以参考其统一任务接口及VLN-CE/ObjectNav评测入口，但代码/权重/评测集发布不等于全部训练数据已经可下载。本轮不另建LightNav依赖环境，也不增加一条大规模数据下载路线。[LightNav-0官方入口](https://github.com/lightorigins/LightNav-0)

先全量盘点本地；外部来源先取得说明、许可和小样本，转换每个合格来源最多10个episode，失败样本占名额、不反复换样。R2R/RxR经NaVILA或其他发布者重复提供的同一原始episode不能被当成不同来源增加额度。场景资产与数据标注的许可分别记录；不因代码开源而推断图像或3D资产可再分发。

## 4. 统一格式与适配规则

沿用schema v2的 `observation / supervision / provenance`，增加必要的字段级有效性与来源记录；如改变语义，提升次版本并提供显式迁移器，不静默改变旧样本。

| 部分 | 必须保留的字段/信息 |
|---|---|
| observation | 固定task/instruction；当前与历史RGB的ID、时间、哈希；标定、pose_reference、frame_id、odom_epoch；可用深度；因果MapView与输入mask；旧Route及版本、旧Local与相对TF、过去执行事实 |
| supervision | Landmark/Local/Route及逐字段标注状态；`[32,2]` reference与有效前缀mask、参考线状态/来源；同线五waypoint或有依据的空列表；TEXT模式；动作/评分均未标注 |
| provenance | 原始来源、版本/许可、layout_family、original_episode、派生关系、source_binding；标注模型或标注人、输入/响应哈希、修订、审核状态；split及可承担的训练任务 |

具体规则：

1. 几何统一米制源车体系x前y左；相机坐标在外参未知时原样保留为独立类型，禁止只改字段名冒充车体系。鱼眼/pinhole分开标定，禁用不适用的投影。
2. 按真实时间对齐观测、历史图像和位姿，记录缺帧、插值范围与误差。静态参考线按弧长重采样；不把它变成0.1秒动作轨迹。
3. 先去除停顿重复点再生成局部参考线；不跨epoch、暂停或时间断点拼接。保存原始轨迹与转换候选；平滑不得切角穿障或改变任务子句。
4. waypoint从同一批准参考线20/40/60/80/100%弧长位置生成。缺失路线、批准空路线、有效路线分开存；录制结束本身不证明STOP或任务完成。
5. 路线语义审核、度量/车体审核、几何可通行审核分别给结论。名义路线与动态避让轨迹分开；静态渲染不能洗掉原轨迹的动态来源。
6. MapView只由该时刻以前的真实深度/观测构建。缺深度则明确不可用，绝不补造BEV；几何层没有语义地标就保存空观测层，不能声称已有语义地图输入。
7. 文本审核按字段赋 `unlabeled / proposed / approved / rejected`；记录有效token范围。无Landmark监督不等于已确认 `[]`，无Local监督不等于已确认 `unknown`。未批准字段/几何不贡献loss。
8. Route的原始任务不可变；训练记录的旧Route来自哪次批准/提议版本必须明确。gold-context与recursive-context分开；修改早期Route后，后续依赖重新校验。
9. 允许完整导航样本、仅语义样本、仅几何样本分别进入适用池。辅助问答可以使用独立任务格式，不强行捏造五标签；默认训练加载器拒绝全无有效监督的样本。
10. 所有动态动作、模态可行性、Scorer字段保持unknown/未标注，loss关闭；不把一个参考线复制成九模态，不以零数组替缺失动作GT。

标注时刻复用 `reference_schedule.py`：最长5秒，并按余量、转向和距线触发提前刷新。每段检查所有源位姿在下一更新前的覆盖，不只检查抽样帧；若转换后的轨迹仍越出参考线，补帧或拒绝该段。无连续位姿的文本辅助样本不伪造此覆盖验收。

## 5. Split与数据泄漏检查

- 官方训练/验证/测试边界保持；跨数据集按底层物理scan/布局ID、原始轨迹和派生链统一分组，避免R2R、RxR、REVERIE及NaVILA包装之间泄漏。
- 先按物理布局族和原episode分组，再切窗、标注和增强。原动态轨迹、静态相机重渲染、同轨迹不同相机/外观变体、重叠窗口必须同组。
- 已反复查看的demo是回归数据，不宣称盲测。当前原始仓库只有一个布局族，不能从同一圈的不同帧构造未见布局验证集；本轮如没有新布局就明确留下该缺口。
- 不跨split将同一已讨论轨迹重新标成新样本。回归角色与训练资格分别保存；当前demo及其直接派生样本优化权重为0。是否使用同布局其他任务及相应seen-layout评测，必须在未来训练配方里单列，不混入unseen-layout结果。
- 教师仅看部署可见输入；未来轨迹、目标真值、实例GT仅在标签生成/核验侧。数据加载层也要检查，不能只在prompt中过滤。

## 6. 可执行工作顺序与交付

以下新增文件/功能是拟实现项；现有 `audit / convert / validate / export` 继续复用，不再做一套通用平台。

| 步骤 | 工作与主要修改位置 | 产物 | 通过条件 |
|---|---|---|---|
| D1 来源清单 | 扩展 `dataset_tools/catalog.py`：格式识别、来源版本、任务/静态性、相机和许可审计 | `source-inventory.json`、`eligibility.csv`、固定候选清单 | 全部本地来源可追溯，缺失字段与拒绝原因保留 |
| D2 格式与监督矩阵 | 更新 `core.py` 的v2适配/校验、`pools.json`草案；区分语义/几何/动作资格 | schema说明、迁移规则、有效监督矩阵 | 缺失监督关闭正确；旧人工导出不损坏 |
| D3 小规模转换 | 先人工/Isaac，再DynaNav；外部连续来源先选一个接入，最多10 episode/来源 | manifest、逐样本记录、失败报告、源/转换对照图 | 时间/坐标/标定通过；任务与静态性不明的路线不入GT池 |
| D4 文本审核与导出接线 | 复用当前提议和批准修订；必要时补字段级审核导出。真实API仅独立小样本验收 | 提议→批准修订→训练记录的来源链 | 无人工批准升级；实际API未执行就明确未通过 |
| D5 配方与划分 | 新增split manifest与只读采样检查，更新阶段配方 | `split-manifest.json`、各池计数、阶段候选配比 | 原始/派生轨迹及布局无跨split泄漏；回归权重0 |
| D6 数据验收 | 统一回放、schema/loss-mask检查、小批数据加载 | `alignment-report.json`、`index.html`、复现命令 | 下列硬检查通过，覆盖不足单独报告 |

## 7. 数据就绪验收

- 所有纳入记录schema、有限数值、源文件哈希、时间单调、坐标往返、Route版本链检查通过；确定性几何误差不超过现有5cm检查尺度。
- 原始instruction不被覆盖；waypoint与批准参考线一致；无未来信息进入输入；缺失字段的loss mask正确；无全未标注样本混入训练manifest。
- 参考线覆盖核验、短线/空线、停止、转向、无地图/无标定、跨epoch与重复轨迹都有成功或明确拒绝样例。
- 每个转换episode都给计数与原因；小规模首批逐个审核全部episode，关键转向/停止/指代帧必须看，不能只抽“看起来成功”的视频。
- 统计原episode数、派生样本数、有效文本/参考线数、批准率、任务/事件/布局分布，不能只报JSON总数或格式成功率。
- 每个纳入训练来源至少有一个真实、可追溯、通过相应字段审核的样本；没有则该池保持禁用。样本不足或没有未见布局时如实记录。
- 输出分别标记：工具可用、格式对齐通过、标签已审核、数据覆盖是否足够。数据就绪不等于训练完成，不要求本轮通过动态Oracle或导航成功率指标。

建议先交付D1–D3的库存与10-episode级转换报告，再据实际合格数据冻结D5配方。暂不承诺大规模数量或训练预算，也不将API接通作为开始数据审计的前置条件。
